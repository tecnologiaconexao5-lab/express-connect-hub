--------------------------------------------------------------------------------
1. ERRO ANTES / REPRODUCAO
--------------------------------------------------------------------------------
Componente: src/components/financeiro/MargemOperacional.tsx
Query ANTES:
  supabase.from("composicao_financeira_os").select(`
    *, os:ordens_servico!inner(numero, cliente)
  `).order("created_at", { ascending: false })
O embed PostgREST `os:ordens_servico!inner(...)` exige um relacionamento
detectavel entre composicao_financeira_os e ordens_servico. Como NAO existe FK,
o PostgREST responde 400 ("Could not find a relationship between
'composicao_financeira_os' and 'ordens_servico'"). => tela falhava com erro.

--------------------------------------------------------------------------------
2. CAUSA RAIZ (schema real)
--------------------------------------------------------------------------------
- composicao_financeira_os: PK id uuid; os_id uuid (SEM FK); cliente_id uuid;
  prestador_id uuid; valor_cliente/valor_prestador/pedagio_valor/margem_liquida/
  percentual_* numeric; created_at; origem_calculo; demais custos.
  FKs de composicao_financeira_os = [] (nenhuma).
- ordens_servico: id uuid (PK); numero text; cliente uuid; prestador uuid;
  cliente_id/prestador_id text; tenant_id uuid; is_teste boolean.
- composicao_financeira_os.os_id -> ordens_servico.id e vinculo SEMANTICO, mas
  NAO e FK. 20 de 59 linhas tem os_id SEM OS correspondente (orfas).
=> Causa raiz = ausencia de FK + uso de embed. Corrigir por FK exigiria resolver
   20 orfaos e nao ha necessidade estrutural -> NAO criar FK (missao: evitar).

--------------------------------------------------------------------------------
3. SOLUCAO ESCOLHIDA (minima, sem migration)
--------------------------------------------------------------------------------
Consulta em ETAPAS (batch) pelo os_id — sem embed:
  1) SELECT composicao_financeira_os (campos usados);
  2) coletar os_ids -> SELECT ordens_servico (id, numero, cliente, is_teste)
     .in("id", osIds);
  3) coletar cliente(uuid) -> SELECT clientes (id, razao_social, nome_fantasia)
     .in("id", cliIds);
  4) montar linhas por os_id (helper puro); OS orfa/sem OS nao derruba a tela.
NENHUMA migration. NENHUMA FK criada. Nenhuma estrutura financeira duplicada.

6. ORIGEM DE CADA VALOR (fonte REAL; sem formula inventada)
--------------------------------------------------------------------------------
- receita / valor cliente ..... composicao_financeira_os.valor_cliente
- custo prestador ............. composicao_financeira_os.valor_prestador
- pedagio ..................... composicao_financeira_os.pedagio_valor
- demais custos ............... imposto_valor/seguro_valor/outros_custos/
                                combustivel_valor/ajudante_valor/adicional_valor/
                                desconto_valor (existem; a tela usa repasse+pedagio)
- margem ...................... composicao_financeira_os.margem_liquida (VALOR REAL
                                ARMAZENADO; fallback receita-prestador-pedagio so se null)
- percentual .................. exibido como margem/receita (razao para UI; nao
                                reescreve o percentual armazenado)
- OS/numero/cliente ........... join em etapas ordens_servico + clientes (por id)
Separacao preservada: valor_cliente (receita) != valor_prestador (custo).
