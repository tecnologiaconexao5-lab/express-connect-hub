1. CAUSA RAIZ
============================================================

ERRO:
  permission denied for schema supabase_migrations
  SQLSTATE 42501

OPERACAO QUE FALHA:
  INSERT INTO supabase_migrations.schema_migrations
  (version, name, statements) VALUES (...)

CONTEXT:
  npx supabase start executa migrations com sucesso,
  mas o INSERT de tracking interno falha.
  Depois disso o CLI desmonta os containers.

ANALISE:
  O Supabase CLI v2.117.0 (Bun-based) conecta ao banco
  local como supabase_admin (login role) e executa
  SET ROLE postgres para operacoes de superuser.

  Com 100+ migrations no projeto, o pipeline de migracao
  leva varios minutos. Durante esse tempo, o connection
  pool do CLI pode reciclar conexoes idle (timeout padrao
  10s do node-postgres). Quando a conexao e reciclada,
  o SET ROLE postgres e PERDIDO.

  O INSERT INTO supabase_migrations.schema_migrations
  entao executa como supabase_admin (nao superuser).
  O schema supabase_migrations e owned por postgres
  (superuser), e supabase_admin nao tem USAGE privilege.

  Resultado: SQLSTATE 42501 (insufficient_privilege).

  NOTA: Este e o mesmo bug documentado em:
  - supabase/cli PR #5895 (role step-down lost)
  - supabase/cli Issue #6244 (pipeline stall)

  O fix do PR #5895 desabilita idle reaping e adiciona
  verify hook, mas o Bun-based CLI (v2.117.0) pode ter
  implementacao propria com o mesmo problema.

  FATOR SECUNDARIO: Docker volumes persistem o schema
  supabase_migrations entre runs. Se o schema foi criado
  por um role diferente em run anterior, o problema persiste.
