2. CAUSA DO UUID NO RELATÓRIO ATUAL
====================================================================

Em buscarDadosFaturamento/buscarDadosFaturamentoDetalhado, ordens_servico.cliente
é o UUID oficial (FK). O código montava o filtro de clientes como
"nome_fantasia.ilike.%<uuid>%,razao_social.ilike.%<uuid>%" — tentava achar o
cliente PELO NOME usando o UUID como texto → nenhum cliente casa → o próprio
UUID caía na coluna "Cliente".

====================================================================
3. CORREÇÃO REALIZADA
====================================================================

Novo resolver resolverClientesPorReferencias():
  - referências que são UUID → clientes.id.in(uuids);
  - referências que são nome (legado) → .or(nome_fantasia/razao_social ilike);
  - mapa chaveado por id E pelos nomes → o.cliente (UUID ou nome) resolve sempre.
Aplicado em buscarDadosFaturamento e buscarDadosFaturamentoDetalhado.
Nenhuma substituição por texto hardcoded.

====================================================================
4. FONTE REAL DO CLIENTE
====================================================================

clientes.id / nome_fantasia / razao_social / cnpj (via resolver, a partir do
UUID oficial ordens_servico.cliente). Nunca UUID na tela nem no PDF.

====================================================================
5. FONTE DO ROMANEIRO / OC / ORDEM DE CARGA
====================================================================

ordens_servico.romaneio (coluna existente — Missão 127-E.1).
Quando vazio → "—". Nunca UUID/OS interna nesta coluna.

====================================================================
6. FONTE DO VEÍCULO / PLACA
====================================================================

ordens_servico.veiculo_tipo / tipo_veiculo + ordens_servico.placa_alocada
→ "Iveco Daily · FSP0I96". Quando ausente → "—". Nunca inventado.

====================================================================
7. FONTE DO VALOR BASE
====================================================================

Derivado para exibição (documentado): Valor Base = valorTotal − adicionais −
pedágio + descontos. O TOTAL (oficial) NUNCA é recalculado — usa
ordens_servico.valor_cliente.

====================================================================
8. FONTE DO KM ADICIONAL
====================================================================

adicionais.jsonb → campo km_excedente quando o objeto de adicionais do pricing
estiver presente (extrairValorJsonb). Quando não disponível → 0 (coluna "—").
PENDÊNCIA estrutural: ordens_servico NÃO possui coluna própria de km adicional
do cliente (está no metadata da alocação/pricing).

====================================================================
9. FONTE DO PEDÁGIO
====================================================================

ordens_servico.pedagio (valor cobrado do cliente). Quando zero → "—".

====================================================================
10. FONTE DO REEMBOLSO
====================================================================

NÃO existe campo de reembolso em ordens_servico → sempre 0 (coluna "—").
PENDÊNCIA estrutural documentada (nada inventado).

====================================================================
11. FONTE DOS DESCONTOS
====================================================================

ordens_servico.descontos (ou desconto, fallback). Exibido como "-R$ X,XX".
Quando zero → "—".

====================================================================
12. FONTE DO VALOR TOTAL
====================================================================

ordens_servico.valor_cliente (total oficial cobrado do cliente — mesma fonte
do "Valor Faturado" do relatório agregado). NÃO recalculado.

14. ESTRUTURA FINAL DO PDF INDIVIDUAL (landscape)
====================================================================

1. CABEÇALHO navy + logo oficial (branco + X colorido) + empresa à direita
   (razão, CNPJ/IE, cidade/UF, contato) + linha laranja.
2. Título "RELATÓRIO DE FATURAMENTO" + subtítulo "Detalhamento dos serviços
   realizados" (NÃO "Relatório Operacional de Faturamento").
3. Identificação do CLIENTE no topo (nome em destaque + CNPJ abaixo) + Período
   + Data de geração (não repetido nas linhas).
4. Tabela (cabeçalho repetido a cada página):
   Data | Romaneio / OC | Veículo / Placa | Valor Base | KM Adic. | Pedágio |
   Reembolso | Descontos | Valor Total
   (trajeto em segunda linha discreta na coluna Romaneio/OC).
5. RESUMO FINANCEIRO + TOTAL FATURADO em destaque (somente após a última linha).
6. Rodapé em todas as páginas: "Conexão Express Transportes LTDA",
   "Gerado em dd/mm/aaaa HH:mm", "Página X de Y".
