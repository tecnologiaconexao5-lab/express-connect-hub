2. REGRA DE TENANT/PERFIL UTILIZADA
--------------------------------------------------------------------------------
Fato estrutural (05D.4): pagamentos_prestadores NAO possui coluna tenant_id, e
prestadores tambem nao possui tenant_id. O vinculo SEGURO de tenant e derivado
do os_id -> ordens_servico / alocacoes_escala (ambas possuem tenant_id).

Helper (SECURITY DEFINER, STABLE, search_path=public):
  public.f_pp_tenant_id(p_os_id uuid) RETURNS uuid
    SELECT COALESCE(
      (SELECT os.tenant_id FROM ordens_servico os WHERE os.id = p_os_id),
      (SELECT ae.tenant_id FROM alocacoes_escala ae WHERE ae.id = p_os_id)
    );
  Grants: REVOKE de PUBLIC/anon; GRANT EXECUTE para authenticated, service_role.
  (resolve o tenant sem disparar RLS de terceiros.)

Policy pp_select_tms:
  FOR SELECT TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM public.tenant_usuarios tu
      WHERE tu.user_id = auth.uid()
        AND tu.status = 'ativo'
        AND tu.tenant_id = public.f_pp_tenant_id(pagamentos_prestadores.os_id)
    )
  );

Regra: leitura liberada SOMENTE se (a) o usuario e um vinculo ativo em
tenant_usuarios e (b) o tenant derivado do registro (via os_id) e IGUAL ao tenant
desse usuario. Perfil: qualquer papel ativo do TMS (financeiro/admin/operacional…),
pois os demais modulos financeiros usam o mesmo criterio de vinculo TMS ativo.
Linhas sem os_id/vinculo resolvivel => tenant NULL => NAO visiveis (default seguro).
