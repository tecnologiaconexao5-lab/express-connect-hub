1. RESUMO EXECUTIVO
----------------------------------------------------------------------------------------------------
Foram resolvidos os dois atritos reportados:

1) Cadastro do Prestador: cada cartao de documento (CNH, CRLV, Contrato, etc.) agora e uma

   imediatamente, sem abrir modais e sem precisar clicar em "Upload".

2) Comercial > Propostas: a exportacao de PDF agora gera um File em memoria e envia

2. DRAG-AND-DROP NATIVO NOS CARTOES DE DOCUMENTO
----------------------------------------------------------------------------------------------------
Arquivo: src/components/prestadores/PrestadorDetalhe.tsx

O que mudou:
- O upload foi extraido para handleDocFile(tipoDocumento, file), reutilizando o fluxo ja
  existente (enviarDocumentoOperacionalPrestador + metadados + estado local).
- Foi adicionada validacao compartilhada validarArquivoAnexo (PDF/JPG/JPEG/PNG/WEBP,
  limite de 50 MB), com toast de erro quando o arquivo e invalido.
- handleDocUpload(tipo, event) permanece como ponte para o input de arquivo e agora
  limpa o input apos a selecao.
- Cada cartao de DOCS_TIPOS (CNH Frente, CNH Verso, Documento Pessoal, Comprovante de
  Residencia, Comprovante Bancario, Contrato, CRLV, Documento do Veiculo, ANTT,
  Apolice de Seguro, Outros) recebeu:
  * onDragOver: preventDefault + destaca o cartao.
  * onDragLeave: limpa o destaque somente quando o ponteiro sai do cartao.
  * onDrop: preventDefault + pega o primeiro arquivo e chama handleDocFile imediatamente.
- Estado dragOverDoc controla o destaque visual:
  border-primary + bg-primary/5 + ring-2 ring-primary/30.
- Texto de apoio adicionado no cartao: "Arraste um PDF/imagem para este cartao ou use Upload."
- O input de arquivo agora aceita tambem .webp.
- Se o prestador ainda nao estiver salvo (sem p.id), o comportamento anterior e mantido:
  o arquivo fica em documentosPendentes para envio apos salvar.
- Nenhum modal adicional foi criado; o drop usa o mesmo fluxo do botao Upload.

3. EXPORTACAO DE PROPOSTA -> CENTRAL DE DOCUMENTOS
----------------------------------------------------------------------------------------------------
Arquivos:
- src/utils/pdfGenerator.ts
- src/components/comercial/propostas/ListaPropostas.tsx
- src/services/comercial/propostaContatoService.ts (NOVO)

3.1 Geracao do PDF como File
- gerarPDFProfissional agora, alem de baixar o PDF (doc.save), retorna um File:
  new File([doc.output("blob")], "<titulo>.pdf", { type: "application/pdf" }).
- Callers antigos continuam funcionando (ignoram o retorno).

3.2 Exportar PDF / Exportar e Guardar
- exportarProposta captura o File retornado e, apos atualizar o estado local/historico,
  chama enviarDocumentoOperacional com:
  * moduloOrigem: "comercial"
  * tipo: "Proposta Comercial"
  * nome: nome do arquivo PDF
  * categoria: "Comercial"
  * departamento: "Comercial"
  * responsavel: "Comercial"
  * clienteId/entidadeId: cliente_id resolvido (quando encontrado)
  * descricao: "Proposta <titulo> exportada em <data/hora>."
- Isso vale para as duas acoes do menu que geram PDF ("Exportar PDF" e
  "Exportar e Guardar"). O download do PDF continua acontecendo.
- Em caso de falha no upload, o PDF ja gerado e mantido e o usuario recebe toast de aviso
  (nao bloqueia a exportacao).
- Em caso de sucesso, toast "Proposta exportada e enviada para a Central de Documentos."

3.3 Resolucao de cliente_id e telefone (CRM)
- Novo service: src/services/comercial/propostaContatoService.ts
- resolverContatoProposta tenta, nesta ordem:
  1. Lead por leadId (se a proposta tiver esse campo).
  2. Lead pela URL da proposta (crm_leads.proposta_url contem "proposta=<id>").
  3. Cliente por clienteId.
  4. Lead por nome/empresa (crm_leads.nome / crm_leads.empresa).
  5. Cliente por nome_fantasia/razao_social.
- Retorna { clienteId, telefone, origem }.
- O telefone prioriza whatsapp e depois telefone, normalizado para a API do WhatsApp
  (somente digitos; prefixo 55 quando necessario).
- A proposta passa a aceitar opcionalmente clienteId/leadId/telefone no tipo Proposta;
  os mocks atuais continuam funcionando por fallback de nome.

4. COMPARTILHAR NO WHATSAPP COM TELEFONE DO CRM
----------------------------------------------------------------------------------------------------
Arquivo: src/components/comercial/propostas/ListaPropostas.tsx

O que mudou:
- A acao do menu passou de "Compartilhar Link" para "Compartilhar no WhatsApp".
- compartilharProposta agora:
  1. Resolve o contato no CRM (lead/cliente).
  2. Copia o link da proposta para a area de transferencia (comportamento anterior).
  3. Monta a mensagem:
     Ola! Segue o link da proposta "<titulo>" da Conexao Express:
     <link>
  4. Abre https://wa.me/<telefone>?text=<mensagem> quando o telefone e encontrado.
  5. Se nao encontrar telefone, abre https://wa.me/?text=<mensagem> e avisa via toast
     que o WhatsApp foi aberto sem destinatario.
- O historico da proposta registra "Link compartilhado no WhatsApp".
