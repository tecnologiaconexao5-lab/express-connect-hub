3. OPÇÃO EQUIVALENTE A `pg_dump --schema-only`
----------------------------------------------------------------------------------------------------
Recomendação principal:
  Usar `supabase db dump` com:
    --db-url <connection string de um usuário READ-ONLY>
    --schema public
    --keep-comments
    --file <novo arquivo>
    --dry-run   (primeiro, para inspecionar o comando)

Equivalência:
  - O `supabase db dump` é documentado como wrapper do pg_dump.
  - `--schema public` limita ao schema public.
  - `--keep-comments` preserva comentários.
  - O padrão sem `--data-only` e sem `--role-only` é extração de schema
    (deve ser confirmado no dry-run e no início do arquivo).
  - NÃO usar `--data-only`.
  - NÃO usar `--no-acl`/`--no-privileges` se o objetivo é preservar grants.
  - `--no-owner` pode ser usado para evitar dependência de ownership, mas
    não deve remover ACL/grants.
  - Se o pg_dump for usado diretamente no futuro:
      pg_dump --schema-only --no-owner --encoding=UTF8
        --file <novo arquivo> <connection string read-only>
    (inclui tabelas, colunas, constraints, índices, sequences, funções,
     triggers, views, policies, RLS e ACLs; roles e objetos de outros schemas
     precisam de inventário separado).

Limitação:
  - O binário pg_dump standalone não está instalado localmente.
  - O caminho via `supabase db dump` precisa ser validado com `--dry-run`
    em uma janela autorizada, pois o CLI pode usar Docker/Management API.
