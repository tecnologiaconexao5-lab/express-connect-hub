subiam para O TOPO e empurravam os recentes (25/09) para baixo — exatamente o sintoma
relatado (HML-FAT-FINAL-01 abaixo de junho/julho).

2. CAMPO ESCOLHIDO E JUSTIFICATIVA
================================================================================
Campo: COALESCE(data_finalizacao, data_escala), DESC. Desempate: id DESC.
- data_finalizacao = data OPERACIONAL de conclusao (quando o servico foi finalizado).
- data_escala = data da operacao (fallback quando data_finalizacao e NULL — casos antigos/App),
  evitando o efeito "NULLS FIRST" e mantendo semantica operacional.
- POR QUE NAO created_at: created_at e a data de INSERCAO do registro; para lancamentos
  retroativos/importados pode divergir da data real do servico. A regra pedida e ordem
  OPERACIONAL (mais recente no topo), representada por data_finalizacao/data_escala.
- created_at continua disponivel (nao usado nesta ordenacao).

Novo helper puro (centralFinanceiroService.ts):
    export function compararCentralFinanceiro(a, b) {
      const da = a.dataFinalizacao || a.data || "";
      const db = b.dataFinalizacao || b.data || "";
      const porData = db.localeCompare(da);            // DESC
      return porData !== 0 ? porData : String(b.id).localeCompare(String(a.id)); // id DESC
    }
    export function ordenarCentralFinanceiro(lista) { return [...lista].sort(compararCentralFinanceiro); }
