## DEDUPLICAÇÃO

**Chave canônica utilizada: `alocacoes_escala.ordem_servico_id === ordens_servico.id`**

- Quando uma **Escala** tem `ordem_servico_id` apontando para uma **OS** do
  prestador no período, a produção é representada **UMA ÚNICA vez** (linha da OS,
  `tipoOrigem='ordem_servico'`), e a escala NÃO gera segunda linha.
- marca-se `origemEscala=true` na linha da OS → rastreabilidade, sem crédito duplicado.
- Escalas **sem** `ordem_servico_id` (ou apontando p/ OS fora do filtro) entram como
  produção própria (`tipoOrigem='escala'`).
- Filtro "Escala" mostra `tipoOrigem==='escala' || origemEscala===true` (as OS que
  vieram da escala) — sem duplicar.
- Filtro "OS" mostra apenas `tipoOrigem==='ordem_servico'`.

**Exemplo comprovado (teste 7):** mesma produção presente em Escala(esc-1 →
os-100) e OS(os-100) → resultado = **1 linha**, valor_servicos = 5000 (não 2×).

## FONTES UTILIZADAS

| Necessidade | Fonte real | Campo |
|-------------|-----------|-------|
| OS (produção) | `ordens_servico` | `prestador_id`, `data`, `status finalizada/concluida` |
| Escala (produção) | `alocacoes_escala` | `prestador_id`, `data_escala`, `status`, `ordem_servico_id` (dedup) |
| Lançamentos manuais | `pagamentos_prestadores` | `origem_lancamento='manual'`, `natureza`, `valor_liquido`, `data_competencia` |
| Cliente | `ordens_servico.cliente_id` / `alocacoes_escala.cliente_id` | filtro por ID (não texto) |
| Valor do prestador | `ordens_servico.custo_prestador` / `alocacoes_escala.valor_base` | real do prestador |
| Adicionais | `ordens_servico.adicionais` / `alocacoes_escala.valor_adicionais` | soma |
| Pedágio | `ordens_servico.pedagio` / `alocacoes_escala.valor_pedagio` | soma |
| Descontos | `ordens_servico.descontos` / `alocacoes_escala.valor_descontos` + débitos manuais | soma |
| Adiantamento | `pagamentos_prestadores` débito (adiantamento/vale) | soma |
| Combustível | `pagamentos_prestadores` débito (combustível) | quando existir; senão 0 |
| Bônus/Reembolso (manual) | `pagamentos_prestadores` crédito manual (descrição) | soma |

**Combustível integrado ao extrato: NÃO (por padrão).** Leitura de movimentos
débito de combustível existe; a integração completa de abastecimento/fornecedores
é missão futura. Ausência → zero corretamente, nada inventado.

## CÁLCULO / RESUMO

`Total Créditos = Serviços + Pedágio + Adicionais + Reembolsos + Bônus`
`Total Débitos = Descontos + Adiantamentos + Combustível`
`VALOR LÍQUIDO = Total Créditos − Total Débitos` (garantido no código e no teste 8).

## REGRA DE DEDUPLICAÇÃO (resumo final)

**Chave canônica: `alocacoes_escala.ordem_servico_id` = `ordens_servico.id`.**
Cada produção financeira é representada por UMA linha: a OS é a referência principal;
a Escala vinculada apenas marca `origemEscala` (não gera linha extra). Escalas sem OS
entram como produção própria. Chaves de linha: `os-{os.id}`, `esc-{esc.id}`, `man-{pag.id}`
— garantem que a mesma operação nunca aparece duas vezes.
