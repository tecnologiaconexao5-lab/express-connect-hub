1. SCHEMA CRIADO
--------------------------------------------------------------------------------
public.lotes_pagamento (cabecalho):
  id uuid PK DEFAULT gen_random_uuid(); tenant_id uuid NOT NULL;
  status text NOT NULL DEFAULT 'preparado' CHECK IN
    ('preparado','enviado','processando','processado','erro','cancelado');
  quantidade_pagamentos int NOT NULL; valor_total numeric NOT NULL;
  provider text; id_externo_provider text; criado_por uuid;
  created_at/updated_at timestamptz NOT NULL DEFAULT now();
  enviado_at/processado_at timestamptz NULL. Index idx_lotes_pagamento_tenant.
public.lotes_pagamento_itens (snapshot por item):
  id uuid PK; lote_id uuid NOT NULL FK -> lotes_pagamento(id) ON DELETE CASCADE;
  pagamento_prestador_id uuid NOT NULL FK -> pagamentos_prestadores(id) ON DELETE CASCADE;
  prestador_id uuid; valor numeric NOT NULL; forma_destino text;
  banco/agencia/conta/digito/tipo_conta/favorecido/documento_favorecido/
  chave_pix/tipo_chave_pix text (SNAPSHOT); created_at timestamptz DEFAULT now().
FK: pagamentos_prestadores.lote_id -> lotes_pagamento(id) ON DELETE SET NULL.

--------------------------------------------------------------------------------
2. FKs / UNIQUES
--------------------------------------------------------------------------------
- fk_pp_lote: FOREIGN KEY (lote_id) REFERENCES lotes_pagamento(id) ON DELETE SET NULL.
- uq_lote_item: UNIQUE (lote_id, pagamento_prestador_id) — impede item duplicado.
- Indices: idx_lotes_pagamento_tenant, idx_lotes_pagamento_itens_lote,
  idx_lotes_pagamento_itens_pag.

--------------------------------------------------------------------------------
3. FLUXO RPC ANTES x DEPOIS
--------------------------------------------------------------------------------
ANTES (05D.7B.1): lock -> guards -> gen UUID -> UPDATE pp (lote_id, em_lote).
DEPOIS (05D.7C.1), tudo em UMA transacao (ALL-OR-NOTHING):
  lock pagamentos (FOR UPDATE)
  -> guards existentes (+ NOVO guard DESTINO_INVALIDO)
  -> validar destino bancario de cada prestador
  -> gen UUID (v_novo)
  -> INSERT lotes_pagamento (status 'preparado', quantidade, SUM(valor_liquido))
  -> INSERT lotes_pagamento_itens (snapshot congelado do prestador)
  -> UPDATE pagamentos_prestadores (lote_id=v_novo, status_pagamento='em_lote')
  -> COMMIT
Se qualquer id/prestador invalido: NAO cria cabecalho, NAO cria item, NAO altera pp.

--------------------------------------------------------------------------------
4. ORIGEM DOS DADOS BANCARIOS / REGRA DE VALIDACAO
--------------------------------------------------------------------------------
Fonte: tabela prestadores (por pagamentos_prestadores.prestador_id).
Destino VALIDO = (chave_pix preenchida) OU (banco E agencia E conta preenchidos).
NAO inventa PIX; NAO completa CPF/CNPJ; NAO usa conta da Conexao.
Sem destino valido -> bloqueio DESTINO_INVALIDO (nao cria nada).

--------------------------------------------------------------------------------
5. SNAPSHOT / IMUTABILIDADE
--------------------------------------------------------------------------------
Cada item do lote congela os campos bancarios do prestador no momento da formacao.
Alterar o cadastro do prestador DEPOIS nao altera o item do lote (provado em E).
A futura execucao bancaria deve usar o SNAPSHOT, nunca o cadastro vivo.

--------------------------------------------------------------------------------
6. RLS
--------------------------------------------------------------------------------
lotes_pagamento: ENABLE RLS; SELECT TO authenticated
  USING (EXISTS tenant_usuarios tu WHERE user_id=auth.uid() AND status='ativo'
         AND tu.tenant_id = lotes_pagamento.tenant_id
         AND tu.papel IN ('super_admin','admin_tenant','financeiro')).
lotes_pagamento_itens: ENABLE RLS; SELECT TO authenticated via JOIN lotes_pagamento
  (mesmo tenant/papel).
- SEM policy de INSERT/UPDATE/DELETE -> a UI comum nao escreve/apaga (a RPC, que e
  SECURITY DEFINER, e a unica autoridade de escrita).
- REVOKE ALL de PUBLIC/anon; GRANT SELECT a authenticated.
- Anon: sem acesso. Prestador: sem acesso ao lote/snapshot geral.
- Snapshot bancario nao e exibido na listagem (apenas "Destino validado").
