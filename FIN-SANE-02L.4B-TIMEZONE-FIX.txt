1. CAUSA RAIZ (confirmada em 02L.4A)
================================================================================
new Date("2026-09-18") interpreta como UTC midnight (2026-09-18T00:00:00Z).
No fuso brasileiro (UTC-3), isso vira 2026-09-17T21:00:00 → exibe "17/09/2026".
O bug retrocede 1 dia em TODAS as datas DATE que passam por new Date().

================================================================================
2. PADRÃO SEGURO (já existente no codebase)
================================================================================
Novos Date(d + "T12:00:00") — usa 12:00 UTC para evitar retrocesso.
Usado em 15+ arquivos: ContasPagar, ConferenciaFinanceira, MargemPorOS, etc.

================================================================================
3. FIX APLICADO — PagamentoPrestadores.tsx
================================================================================
Helper fmtDateLocal adicionado no topo do arquivo (após TODOS_PRESTADORES_VALUE):

  function fmtDateLocal(d: string | null | undefined): string {
    if (!d) return "—";
    if (/^\d{4}-\d{2}-\d{2}$/.test(d)) {
      const [y, m, day] = d.split("-").map(Number);
      return new Date(y, m - 1, day).toLocaleDateString("pt-BR");
    }
    return new Date(d).toLocaleDateString("pt-BR");
  }

Detecta DATE puro (10 chars, YYYY-MM-DD) e usa Date(y, m-1, day) (timezone local).
Timestamps completos seguem o fluxo normal (UTC já embutido no ISO).
