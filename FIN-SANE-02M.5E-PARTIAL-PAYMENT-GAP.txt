==========================================================================
SECAO 3 — RPC f_registrar_baixa_financeira (SUPORTE COMPROVADO)
==========================================================================

Esta RPC JA IMPLEMENTA pagamento parcial completo:

  1. Calcula saldo: v_saldo := v_valor_original - v_total_baixado
  2. Valida: v_saldo > 0 (nao quitado)
  3. Valida: p_valor_baixado <= v_saldo (nao excede saldo)
  4. Calcula novo saldo: v_novo_saldo := v_saldo - p_valor_baixado
  5. Define status:
     IF v_novo_saldo > 0 THEN v_novo_status := 'parcial'
     ELSE v_novo_status := 'pago'
  6. Cria baixa com valor_original, valor_baixado, saldo_restante
  7. Atualiza FP com status, data_pagamento, observacoes

  RESTRICOES:
  - Rejeita: status 'pago'/'paga' (ja quitado)
  - Rejeita: status 'cancelado'/'cancelada'
  - Rejeita: valor > saldo
  - Rejeita: saldo <= 0


==========================================================================
SECAO 4 — RPC f_confirmar_pagamento_prestador (SEM SUPORTE)
==========================================================================

Esta RPC NAO ACEITA pagamento parcial:

  1. Busca FP por: os_id + valor = v_valor + status NOT IN ('pago',...)
  2. Calcula: v_saldo = fp.valor - total_baixado
  3. Valida: v_saldo = v_valor (EXATO)
  4. Se v_saldo <> v_valor: REJEITA
  5. Cria baixa INTEGRAL (valor_original=v_valor, valor_baixado=v_valor, saldo=0)
  6. Atualiza FP para status='pago'
  7. Atualiza PP para status_pagamento='pago'

  BLOQUEIO: A linha IF v_saldo <> v_valor impede qualquer pagamento parcial.

SECAO 10 — GAP IDENTIFICADO: RPC f_confirmar_pagamento_prestador
==========================================================================

O UNICO gap funcional esta na RPC f_confirmar_pagamento_prestador.

Problema: A RPC busca FP por:
  fp.valor = v_valor AND fp.status NOT IN ('pago',...)

Se FP.status = 'parcial' e fp.valor = 652,86:
  - RPC encontra o FP (valor = 652,86, status = 'parcial')
  - Calcula: v_saldo = 652.86 - 520 = 132.86
  - Valida: v_saldo (132.86) = v_valor (132.86) -> OK!
  - Cria baixa integral de 132,86
  - Atualiza FP para 'pago'
  - Atualiza PP para 'pago'

FUNCIONA! A RPC ja encontra o FP correto porque:
  - Busca por fp.valor = v_valor (652,86 = 652,86)
  - Nao por fp.valor = v_saldo
  - E v_saldo = 132,86 = v_valor -> valida

PORÉM: Se o usuario tentar pagar 132,86 como Pagamento Prestador:
  - PP.valor_liquido = 652,86
  - v_valor = 652,86 (PP.valor_liquido)
  - Busca FP com fp.valor = 652,86 -> ENCONTRA
  - v_saldo = 652,86 - 520 = 132,86
  - 132,86 <> 652,86 -> REJEITA!

O BUG: O PP fluxo usa PP.valor_liquido como v_valor, nao o saldo real.
Se PP.valor_liquido = 652,86 mas saldo = 132,86, a validacao falha.
