SECAO 5 — DRAFT
-----------------

Implementacao:
  DRAFT_KEY= conexao_prestador_draft
  DRAFT_STORAGE= localStorage
  DRAFT_KEY_STRATEGY= chave unica (somente 1 draft de prestador por vez)

  saveDraft(): serializa campos textuais para localStorage
  loadDraft(): lee e parseia JSON
  clearDraft(): remove do localStorage

  Campos salvos (DRAFT_FIELDS):
    nomeCompleto, nomeFantasia, cpfCnpj, rgIe, dataNascimento,
    telefone, whatsapp, email, rntrc, antt,
    tipoParceiro, status, liberadoApp,
    regiaoPrincipal, origemCadastro, indicacao, disponibilidade,
    turnosPreferenciais, restricoesOperacionais,
    banco, agencia, conta, digito, tipoConta, favorecido,
    cpfCnpjFavorecido, chavePix, tipoChavePix,
    valores financeiros, pagamento, endereco (JSONB)

  NAO salvos:
    documentos (File objects) — impossivel serializar
    veiculos (complexos demais)
    senha, tokens, credenciais — PROIBIDO

CREATE_DRAFT_RECOVERY=
  useEffect no mount: loadDraft() → merge com defaults
  Se draft existe → restore no state

DRAFT_CLEARED_AFTER_CONFIRMED_SAVE= clearDraft() antes de onBack()
DRAFT_PRESERVED_AFTER_FAILED_SAVE= NAO limpa no catch

BINARY_FILES_STORED_IN_DRAFT=NO
PASSWORDS_STORED_IN_DRAFT=NO
TOKENS_STORED_IN_DRAFT=NO
AUTOMATIC_DATABASE_SAVE=NO

---------------------------------------------------------

SECAO 6 — EDICAO DE REGISTRO EXISTENTE
-----------------------------------------

Decisao: NAV GUARD para edicao (sem draft para edit)

Justificativa:
  - Edit envolve dados do banco que podem ser atualizados por outros
  - Draft de edit poderia sobrescrever dados mais recentes
  - Complexidade de isolar por prestador_id + timestamp
  - Nav guard (useBlocker) ja protege contra perda acidental

EDIT_UNSAVED_PROTECTION= useBlocker + beforeunload (mesmo mecanismo)

---------------------------------------------------------

SECAO 7 — SAVE + DRAFT INTEGRATION
--------------------------------------

CREATE save:
  INSERT → reread → clearDraft() → toast.success → onBack()

UPDATE save:
  UPDATE → reread → toast.success → onBack()
  (sem draft para edit)

Save falha:
  catch → toast.error → form aberto → draft preservado

DRAFT_CLEARED_AFTER_CONFIRMED_SAVE=YES
DRAFT_PRESERVED_AFTER_FAILED_SAVE=YES

---------------------------------------------------------

SECAO 8 — DESCARTAR ALTERACOES
---------------------------------

 Dialog "Alterações não salvas":
  - "Continuar editando" → cancela navegacao, mantem form
  - "Descartar alterações" → clearDraft() + navega

Usuario pode:
  - Confirmar descarte (draft removido, navegacao permitida)
  - Cancelar e continuar editando

NENHUM delete de registro existente do banco.
