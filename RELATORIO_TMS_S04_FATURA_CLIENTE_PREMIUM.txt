3. ORIGEM REAL DOS DADOS (FASE 1 — só o que existe)
====================================================================

- Itens:        tabela `fatura_itens` (snapshot imutável):
                os_id (UUID), romaneio, descricao ("OS-XXXX — trajeto"),
                data_servico, valor_base, valor_adicionais,
                valor_descontos, valor_total, km_excedente,
                pedagio_cliente, ajudante_cliente, diaria_cliente,
                saidas_adicionais_cliente.
- Cliente:      `clientes` via buscarClienteParaFatura → razaoSocial,
                nomeFantasia, cnpj, ie, inscricaoMunicipal, endereco,
                cidade, uf, enderecoCompleto, vencimentoPadraoDias,
                tipoCobranca.
- Conexão Exp.: `configuracoes_fiscais` (razao/fantasia/cnpj/ie/im/endereço/
                cidade/uf/telefone/email) via buscarDadosEmpresaParaFatura.
- Bancário:     `contas_financeiras_config` (banco/agência/conta/PIX) +
                snapshot por fatura em metadata.contaBancaria (PDFs
                históricos não mudam quando a conta muda).
- Nº Fatura:    faturas.numero OU metadata.numeroManual.
- Emissão:      faturas.data_emissao.
- Período:      faturas.competencia_inicio / competencia_fim.
- Vencimento:   faturas.vencimento.
- OS interna:   NÃO há coluna os_numero em fatura_itens. O número é
                recuperado do snapshot da descricao ("OS-XXXX — trajeto").
- Romaneio/OC:  fatura_itens.romaneio.
- Serviço/Tr.:  fatura_itens.descricao (trajeto extraído após o "—").
- Valor/Adic./Desc./Total: valor_base/valor_adicionais/valor_descontos/
                valor_total (+ descontos/acréscimos no cabeçalho).
- NFS-e/CT-e:   NÃO armazenados na fatura — NÃO disponível no input do PDF.
- Observações:  faturas.observacao (fatura manual: obs. interna NÃO sai no PDF).

NADA foi inventado; dados ausentes estruturalmente foram documentados (nº OS
como coluna e NFS-e/CT-e vinculados).

4. ESTRUTURA ANTERIOR DO PDF (modelo conexao_express)
====================================================================

1. Faixa navy com logo claro + "FATURA DE SERVIÇOS" + Nº/Emissão/Vencimento
2. Emitente + Cliente (blocos de texto simples)
3. Tabela: Data | OS Interna | Romaneio/OC | Descrição | Valor
   → "OS Interna" exibia o UUID de os_id (fatura_itens.os_id)!
4. Totais em linhas de texto (Subtotal/Acréscimos/Descontos/TOTAL)
5. Observação + Dados para pagamento
6. Rodapé simples sem paginação real completa

====================================================================
5. ESTRUTURA FINAL (PADRÃO DEFINITIVO DO DOCUMENTO DO CLIENTE)
====================================================================

1. CABEÇALHO INSTITUCIONAL navy + logo oficial (branco + X colorido) à
   esquerda + empresa em branco à direita (razão, CNPJ/IE/IM, cidade/UF,
   contato) + linha de acento laranja.
2. Título "FATURA DE SERVIÇOS DE TRANSPORTE" + status comercial traduzido
   (Rascunho/Cancelada — nunca draft/pending/issued).
3. IDENTIFICAÇÃO (caixa leve): Fatura nº (destaque) | Emissão / Vencimento /
   Período ("dd/mm/aaaa a dd/mm/aaaa").
4. CLIENTE (caixa): Razão Social, Nome Fantasia, CNPJ/CPF, Inscrição
   Estadual, Endereço, Cidade/UF — somente campos preenchidos, sem UUID.
5. RESUMO DA FATURA: Quantidade de serviços, Subtotal, Adicionais (se >0),
   Descontos (se >0), TOTAL DA FATURA.
6. TABELA: Data | OS Conexão | Romaneio / OC | Serviço / Trajeto |
   Valor Base | Adicionais | Total.
7. DOCUMENTOS FISCAIS (somente quando houver informação real — estrutural).
8. CONDIÇÕES DE PAGAMENTO: Vencimento, Prazo (vencimento_padrao do cliente),
   Forma de pagamento, Banco/Agência/Conta/PIX reais.
9. OBSERVAÇÕES (somente observações reais).
10. FAIXA FINAL: TOTAL DA FATURA (laranja institucional).
11. RODAPÉ em todas as páginas: "Conexão Express Transportes LTDA — Fatura
    nº X", "Gerado em dd/mm/aaaa HH:mm", "Página X de Y".

9. ESTRUTURA DA TABELA DE SERVIÇOS
====================================================================

| Data | OS Conexão | Romaneio / OC | Serviço / Trajeto | Valor Base | Adicionais | Total |

- OS Conexão = número interno (recuperado do snapshot; NUNCA UUID).
- Romaneio/OC = referência do cliente (fatura_itens.romaneio).
- Serviço/Trajeto = texto natural extraído ("Guarulhos › Morumbi").
- Larguras somam 515pt (sem estouro) + cabeçalho repetido a cada página.

====================================================================
10. OS CONEXÃO x ROMANEIRO/OC (não confundidos)
====================================================================

SIM — colunas distintas. OS Conexão = número interno (ex.: OS-2026-100).
Romaneio/OC = referência comercial do cliente (ex.: 343550).
Quando ausentes → "—". Nenhum UUID.

====================================================================
11. ADICIONAIS
====================================================================

Coluna "Adicionais" mostra o valor real do item (valor_adicionais) quando
> 0, senão "—". O RESUMO traz o total de acréscimos da fatura.
As colunas de composição (km_excedente, pedagio_cliente, ajudante_cliente,
diaria_cliente, saidas_adicionais_cliente) existem na tabela e são
transportadas no item; NÃO são somadas novamente para não duplicar
(cálculo original preservado).

portanto NÃO é preenchida (nada inventado) → "NÃO DISPONÍVEL" no input.
