DOIS métodos estão documentados e em uso ativo no repositório:

  MÉTODO A — Programático (Supabase JS Client via signInWithPassword)
  ──────────────────────────────────────────────────────────────────────
  Usado por: 30+ spec files (FIN-362/363, financeiro-rls-seguranca, a23, tms0064, etc.)
  Como funciona:
    1. const client = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)
    2. await client.auth.signInWithPassword({ email, password })
    3. Retorna session.access_token (JWT) — client fica autenticado automaticamente
    4. Todas as queries .from() subsequentes usam o JWT da sessão
  Não requer browser. Não requer Playwright. Funciona em Node.js puro.
  É o padrão usado por todas as missões FIN-362/363 que passaram E2E.

  MÉTODO B — Browser (Playwright login page)
  ──────────────────────────────────────────────────────────────────────
  Usado por: helpers/auth.ts + 46+ spec files
  Como funciona:
    1. page.goto("/login")
    2. page.fill('input[type="email"]', email)
    3. page.fill('input[type="password"]', password)
    4. page.click('button[type="submit"]')
    5. AuthContext do React chama Supabase signInWithPassword internamente
  Requer Playwright + browser headless. Mais lento (~3-5s vs ~200ms do Método A.

  RECOMENDAÇÃO PARA REC-06.2B.1: MÉTODO A (programático)
  Justificativa: mais rápido, sem browser, sem localhost, sem Playwright config.
