1. OBJETIVO
-----------
Criar ponte (bridge) automática entre a tabela `prestadores` (criados pelo App
Motorista com origem_cadastro='app_motorista') e `recrutamento_candidatos` para
que motoristas que se cadastram no App apareçam automaticamente no Kanban de
Recrutamento do TMS, sem duplicação de registros.

2. PROBLEMA IDENTIFICADO (AG-07J READ-ONLY)
--------------------------------------------
- App cria prestador com status='em_analise', liberado_app=false
- Prestadores App ficam invisíveis no Kanban de Recrutamento
- Nenhuma tabela conecta App → Kanban
- Migration AG-07F (f_buscar_operacoes_motorista) não aplicada em produção
- Gap J-3: App prestadores não alimentam pipeline de recrutamento

3. ARQUITETURA DA SOLUÇÃO
--------------------------
  App Motorista → prestadores (origem='app_motorista')
                         │
                         ▼
  enterpriseKanbanService.listar()
       │
       ├── buscarECadastrarAppPrestadores()
       │     ├── SELECT prestadores WHERE origem_cadastro = 'app_motorista'
       │     ├── SELECT recrutamento_candidatos WHERE prestador_id IS NOT NULL
       │     ├── Filtra novos (sem prestador_id no Kanban)
       │     ├── INSERT em recrutamento_candidatos (com prestador_id)
       │     └── Retorna EnterpriseCandidate[]
       │
       ├── SELECT recrutamento_candidatos ORDER BY data_atualizacao
       │
       └── applyFilters (busca, score, tags, etc.)
                         │
                         ▼
              EnterpriseCandidate[] → Kanban UI

6. PROTEÇÕES CONTRA DUPLICAÇÃO
-------------------------------
- Query de verificação: `SELECT prestador_id FROM recrutamento_candidatos WHERE prestador_id IS NOT NULL`
- Set de IDs existentes construído antes do insert
- Apenas prestadores cujo ID NÃO está no set são inseridos
- Segunda chamada de listar() não cria segundo candidato (test B)
- Candidato existente + mesmo prestador não duplica (test C)

7. SEQUÊNCIA DE EXECUÇÃO (RACE CONDITION FIX)
----------------------------------------------
ANTES: Promise.all([buscarECadastrarAppPrestadores(), queryKanban])
DEPOIS: await buscarECadastrarAppPrestadores(); then queryKanban

Motivo: A query Kanban precisa rodar DEPOIS do bridge inserir os novos
candidatos, caso contrário retorna dados incompletos.

8. BUG CORRIGIDO: applyFilters DEFENSIVO
-----------------------------------------
PROBLEMA: applyFilters() acessava .length em arrays potencialmente undefined
  - filtros.prioridade.length → TypeError quando prioridade é undefined
  - Similar para statusDocumental, validadeCNH, tags, statusOperacional,
    disponibilidade
  - Erro era engolido pelo catch silencioso em listar(), retornando []

SOLUÇÃO: Adicionado optional chaining (?) em todas as verificações de array:
  - filtros.prioridade?.length
  - filtros.statusDocumental?.length
  - filtros.validadeCNH?.length
  - filtros.tags?.length
  - filtros.statusOperacional?.length
  - filtros.disponibilidade?.length
