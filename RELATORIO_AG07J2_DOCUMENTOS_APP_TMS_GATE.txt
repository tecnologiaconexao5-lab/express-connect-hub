4. GAPS IDENTIFICADOS
======================

GAP J.2-1: APROVAÇÃO DESCONECTADA (P1)
  AnaliseDocumentoIA escreve em documento_analises
  NÃO propaga para documentos_prestadores.status
  Impacto: documentos永远ficam com status=pendente no gate
  Solução: sync documento_analises → documentos_prestadores

GAP J.2-2: FAIL-OPEN NO GATE DOCUMENTAL (P2)
  verificarElegibilidadeDocumental retorna elegivel=true em caso de erro
  Impacto: prestador com docs vencidos pode ser alocado se DB falhar
  Solução: decisao do usuário (manter fail-open ou harden)

GAP J.2-3: AnaliseLote USA TABELA ERRADA (P2)
  SELECT de "provider_documents" em vez de "documentos_prestadores"
  Impacto: componente mostra dados de tabela inexistente
  Solução: corrigir tabela para documentos_prestadores

GAP J.2-4: SEM SUBSTITUIÇÃO DE DOCUMENTO NO APP (P3)
  App não tem tela para enviar novo documento após rejeição/vencimento
  Impacto: motorista deve re-cadastrar inteiramente
  Solução: adicionar tela de substituição no App (futuro)

GAP J.2-5: STATUS DEFAULT = pendente (P3)
  Upload do App insere com status=pendente (default)
  Nenhum fluxo automático muda para 'valido' ou 'aprovado'
  Impacto: gate documental pode bloquear indevidamente
  Solução: definir regra de status pós-upload
