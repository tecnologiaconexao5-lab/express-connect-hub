SEÇÃO 1 — SEMÂNTICA DAS TRÊS TABELAS
══════════════════════════════════════════════════════════════════════════════════

1.1 financeiro_pagar (FP)
─────────────────────────
  Função: TÍTULO a pagar — representação contábil da obrigação financeira
  Escopo: 1 FP por OS (UNIQUE os_id)
  Campo valor: deve representar o TOTAL que o prestador tem direito a receber
  Status lifecycle: pendente → aberto → pago
  Baixa via: financeiro_baixas (título_tabela = 'financeiro_pagar')
  Uso no DRE: NÃO — DRE usa pagamentos_prestadores
  Uso no Fluxo de Caixa: SIM — "Previsto Saída" = soma FP.valor (títulos abertos)
  Uso no Fluxo de Caixa Realizado: SIM — "Realizado Saída" = soma financeiro_baixas.valor_baixado
  Fonte de criação: trigger f_trg_propagar_financeiro_alocacao (M66) ou f_trg_propagar_financeiro_os (M80)

1.2 pagamentos_prestadores (PP)
───────────────────────────────
  Função: CONFERÊNCIA + TÍTULO DE PAGAMENTO — registro que o prestador deve ser pago
  Escopo: 1 PP por OS (UNIQUE os_id)
  Campo valor_liquido: obrigação total do prestador (repasse + pedagio + adicional + outros_custos)
  Campo valor_servicos: repasse-base (serviços puros)
  Campo pedagio: pedagio separately tracked
  Campo adicionais: adicionais separately tracked
  Status lifecycle: pendente → em_lote/programado → pago
  Uso no DRE: SIM — "Custo Prestador" = PP.valor_liquido WHERE impacto_dre=true AND status='pago'
  Uso no Fluxo de Caixa: NÃO — Fluxo usa FP e baixas, não PP diretamente
  Fonte de criação: trigger f_trg_propagar_financeiro_alocacao (M66) ou f_trg_propagar_financeiro_os (M80)

1.3 composicao_financeira_os (CF)
──────────────────────────────────
  Função: MARGEM/ANÁLISE — decomposição da compose financeira da OS
  Escopo: 1 CF por OS (UNIQUE os_id)
  Campo valor_cliente: receita do cliente
  Campo valor_prestador: repasse-base (NÃO inclui pedagio/adicional)
  Campo pedagio_valor: pedagio separately
  Campo outros_custos: adicionais + ajudante - descontos
  Campo margem_bruta: valor_cliente - valor_prestador - pedagio - outros_custos
  Uso: Relatórios de margem, não afeta DRE nem Fluxo de Caixa
  Fonte de criação: trigger (mesmo INSERT que FP/PP)

1.4 financeiro_baixas (FB)
──────────────────────────
  Função: REGISTRO DE PAGAMENTO EFETIVO — evidência de que o dinheiro saiu
  Relação: 1:N com FP (vários pagamentos parciais possíveis)
  Campo valor_baixado: quanto foi efetivamente pago nesta baixa
  Campo valor_original: valor do título no momento da baixa
  Campo saldo_restante: 0 (baixa integral) ou > 0 (parcial)
  Uso no Fluxo de Caixa: SIM — "Realizado Saída" = soma FB.valor_baixado
  Criação: RPC f_confirmar_pagamento_prestador (automática) ou INSERT direto (manual)

SEÇÃO 4 — FLUXO DE PAGAMENTO/BAIXA
══════════════════════════════════════════════════════════════════════════════════

4.1 Fluxo correto (pós-02B)
────────────────────────────
  1. OS/escala criada → trigger M66/M80 → INSERT FP (valor=v_liquido) + INSERT PP (valor_liquido=v_liquido)
  2. Usuário clica "Marcar Pago" na UI → chamada confirmarPagamento(pp_id)
  3. confirmarPagamento() → RPC f_confirmar_pagamento_prestador(p_pagamento_id)
  4. RPC busca PP → extrai v_valor = PP.valor_liquido
  5. RPC busca FP com mesmo os_id E mesmo valor → se não encontrar 1, REJEITA
  6. RPC calcula saldo = FP.valor - baixas anteriores
  7. Se saldo ≠ v_valor → REJEITA ("pagamento parcial não permitido")
  8. Se saldo = v_valor → INSERT financeiro_baixas + UPDATE FP status='pago' + UPDATE PP status='pago'

4.2 Fluxo atual (com bug M66)
──────────────────────────────
  1. OS/escala criada → trigger → INSERT FP (valor=520) + INSERT PP (valor_liquido=652,86)
  2. Usuário clica "Marcar Pago"
  3. RPC busca PP → v_valor = 652,86
  4. RPC busca FP com mesmo os_id E valor=652,86 → NÃO ENCONTRA (FP tem 520)
  5. RPC REJEITA: "Nao existe titulo financeiro aberto, da mesma OS e com o mesmo valor do pagamento."
  6. → Pagamento NÃO PODE ser confirmado via fluxo正规

4.3 Como CESAR foi pago (evidência 02M.5A)
──────────────────────────────────────────
  FP (520) foi baixado com R$520 via INSERT direto em financeiro_baixas
  (valor_baixado=520, valor_original=520, saldo_restante=0)
  PP foi atualizado para status='pago'
  Mas: PP.valor_liquido=652,86 ≠ FP.baixado=520
  → Pagamento parcial sem tratamento adequado

4.4 Fluxo de componentes (pedágio/adicional/etc.)
──────────────────────────────────────────────────
  No trigger:
    v_valor_prestador = NEW.valor_repasse          (base)
    v_pedagio_valor = NEW.valor_pedagio            (pedágio)
    v_adicional_valor = NEW.valor_adicional        (adicional)
    v_ajudante_valor = NEW.valor_ajudante          (ajudante)
    v_desconto_valor = NEW.valor_desconto          (desconto)
    v_outros_custos = v_pedagio + v_adicional + v_ajudante - v_desconto
    v_valor_liquido = v_valor_prestador + v_outros_custos

  No INSERT de FP (M66 atual/bug):
    valor = v_valor_prestador  ← SOMENTE repasse-base
    (pedágio/adicional/etc. NÃO entram no FP)

  No INSERT de PP (M66 atual):
    valor_liquido = v_valor_liquido  ← TOTAL (repasse + pedágio + adicional + ...)
    valor_servicos = v_valor_prestador  ← repasse-base
    pedagio = v_pedagio_valor  ← pedágio
    adicionais = v_outros_custos  ← outros_custos

  REGRA CORRETA (02B):
    FP.valor = v_valor_liquido  ← TOTAL (igual ao PP)
