===============================================================================
CAUSAS RAIZ
===============================================================================

--- Causa #1 — Coluna `cep` em `prestadores` ---
  Schema real (migration 20260510000001_core_baseline.sql linhas 85-167):
  CREATE TABLE public.prestadores (
      id uuid NOT NULL DEFAULT uuid_generate_v4(),
      nome_completo text,
      cpf_cnpj text,
      telefone text,
      ...
      regiao_principal text,
      endereco jsonb,
      ...
      status text DEFAULT 'ativo'::text,
      ...
  );
  A tabela NAO TEM coluna `cep`. Enderecos sao armazenados como JSONB na
  coluna `endereco`.

--- Causa #2 — Coluna `termica` em `veiculos` ---
  Schema real (migration 20260510000001_core_baseline.sql linhas 172-210):
  CREATE TABLE public.veiculos (
      id uuid NOT NULL DEFAULT uuid_generate_v4(),
      placa text,
      tipo_veiculo text,
      ...
      capacidade_kg numeric,
      capacidade_m3 numeric,
      prestador_vinculado uuid,
      status text DEFAULT 'disponivel'::text,
      ...
      tipo_carga text,
      temperatura_min numeric,
      temperatura_max numeric,
      ...
  );
  A tabela NAO TEM coluna `termica`. Colunas similares disponiveis:
  - `tipo_carga` (pode conter 'refrigerada')
  - `temperatura_min` / `temperatura_max` (faixa de temperatura)

--- Causa #3 — Coluna `os_id` e FK em `portal_ocorrencias` ---
  Gap de migration: Duas migrations criam portal_ocorrencias:
  1. 20260509000003_tabelas_faltantes.sql (linha 114) — cria SEM `os_id`:
     CREATE TABLE IF NOT EXISTS public.portal_ocorrencias (
         id uuid, cliente_id uuid, tipo text, descricao text,
         prioridade text, status text, created_at timestamptz,
         updated_at timestamptz
     );
  2. portal_cliente_enterprise.sql (linha 46) — cria COM `os_id`:
     CREATE TABLE IF NOT EXISTS public.portal_ocorrencias (
         id uuid, cliente_id uuid, os_id uuid, prestador_id uuid,
         veiculo_id uuid, ...
     );
  Porem `IF NOT EXISTS` impede a execucao porque a tabela ja existe.
  As colunas adicionais (`os_id`, `prestador_id`, `veiculo_id`, `anexos`,
  `metadata`) nunca foram adicionadas.

  Comentario na migration original (linha 124):
    -- FK sera adicionado pelo arquivo portal_cliente_enterprise.sql

--- Correcao #1 — RoteirizadorWeb.tsx linha 155 ---
  Query original (ERR 400):
    .select("id, nome_completo, veiculos, status, cep, regiao_principal")
    .eq("status", "ativo")

  Query corrigida:
    .select("id, nome_completo,
             veiculos!prestador_vinculado(tipo_veiculo, placa,
                                          capacidade_kg, capacidade_m3, status),
             status, regiao_principal")
    .eq("status", "ativo")

  Alteracoes:
  - `veiculos` -> `veiculos!prestador_vinculado(tipo_veiculo, placa,
     capacidade_kg, capacidade_m3, status)` — usa FK real `prestador_vinculado`
  - `cep` REMOVIDO (nao existe). A linha 105 ja extrai cep de `endereco->>'cep'`

  Linhas que usam `cep` e `veiculos`: 105, 133, 155, 185, 186, 189
