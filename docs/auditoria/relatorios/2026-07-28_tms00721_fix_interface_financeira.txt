RESUMO
------
Na FASE 9 da homologacao da propagacao financeira M66, 3 bugs de runtime
impediam a visualizacao correta da interface financeira. Este relatorio
documenta a correcao dos 3 bugs.

  B1 (P0) - ContasReceberEnterprise.tsx:150
            ReferenceError: page is not defined — state/const dentro de onClick
  B2 (P0) - PagamentoPrestadores.tsx:199 + 8 sitios
            toLocaleString em null/undefined — React crash
  B3 (P1) - PagamentoPrestadores.tsx:307
            contas_financeiras nao existe — PGRST205 404


B1 — ContasReceberEnterprise: page/PAGE_SIZE/totalCount fora de escopo
-----------------------------------------------------------------------
Problema: page, setPage, totalCount, setTotalCount e PAGE_SIZE estavam
declarados dentro de uma arrow function onClick, tornando-os inacessiveis
para a funcao fetchRecebiveis().

Correcao: movidos 3 useState + 1 const para o escopo do componente,
antes do primeiro useEffect.

  const [page, setPage] = useState(1);
  const [totalCount, setTotalCount] = useState(null);
  const PAGE_SIZE = 25;


B2 — PagamentoPrestadores: fmtMoeda com guarda null/undefined
--------------------------------------------------------------
Problema: 8 chamadas desprotegidas a .toLocaleString() em valores que
podem ser null/undefined do banco.

Correcao: criada funcao fmtMoeda com guarda ?? 0:

  const fmtMoeda = (v: number | null | undefined): string =>
    (v ?? 0).toLocaleString("pt-BR", { style: "currency", currency: "BRL" });

3 formatters locais "const fmt" redirecionados para fmtMoeda.
Todos os 8 sitios substituidos.


B3 — PagamentoPrestadores: contas_financeiras inexistente
----------------------------------------------------------
Problema: supabase.from("contas_financeiras").select(...) retorna PGRST205
404 porque a tabela nunca foi criada no Supabase remoto.

Correcao: funcao substituida por setContasFinanceiras([]) — o dropdown ja
trata visualmente array vazio com mensagem "Nenhuma conta cadastrada".
