3. MATRIZ DE SEGURANCA
================================================================================
A) ACOES 100% EXTERNAS AO BANCO DO TMS (permitidas no probe)
   - Criar HttpClient mTLS (Deno.createHttpClient) com cert/key dos Secrets.
   - fetch HTTPS para o host HML da Efi (handshake TLS; GET sem token).
   - Ler variaveis de ambiente dos Secrets (sem persistir/imprimir valores).
   - Retornar JSON sanitizado (runtime, booleanos, status HTTP, classe de erro).
   - Registrar (se houver) apenas metadados nao sensiveis da invocacao.

   - importar @supabase/supabase-js / createClient.

4. HARD GUARDS — POSSIBILIDADE (NAO IMPLEMENTADO NESTA MISSAO)
================================================================================
4.1 GUARD DE AMBIENTE  (viavel e recomendado)
   if ((Deno.env.get("EFI_ENVIRONMENT") || "") !== "homologacao") {
       return 503 / abortar imediatamente;   // nunca prossegue fora de HML
   }
   - Viabilidade: TRIVIAL (verificacao de string no inicio do handler).

4.2 ALLOWLIST DE HOSTNAME (viavel e recomendado)
   const HOSTS_HML_OK = new Set([
       "pix-h.api.efipay.com.br",
       "cobrancas-h.api.efipay.com.br",
   ]);
   const host = new URL(Deno.env.get("EFI_API_BASE_URL_HML") || DEFAULT).hostname;
   if (!HOSTS_HML_OK.has(host)) return 503 / abortar;
   - Viabilidade: TRIVIAL. Impede chamada acidental a producao Efi mesmo com
     variavel de ambiente mal configurada.

4.3 OUTROS GUARDS RECOMENDADOS (viaveis)
   - Proibir import de supabase-js (revisao de codigo / lint).
   - Token interno obrigatorio (ja existe): sem token => 503; token errado => 401.
   - Timeout curto (ja existe: 8s) + AbortController.
   - Resposta sanitizada (ja existe): nunca retorna cert/key; erro por classe.
   - Sem console.log de payload/segredos (manter).
   - Method allowlist (GET/OPTIONS apenas) — opcional.

  Status: NENHUM desses guards 4.1/4.2 foi implementado (missao proibe alterar
  arquivos). Sao pre-requisitos OBRIGATORIOS antes de qualquer deploy futuro.

5. PROVA SEM CLIENT ID / SECRET
================================================================================
  - PERGUNTA: o probe roda sem Client ID/Secret apenas para provar
    carregamento de cert/key + criacao de HTTP client + handshake TLS + resposta HTTP?
  - RESPOSTA: SIM.
      * O probe NAO usa EFI_CLIENT_ID_HML nem EFI_CLIENT_SECRET_HML.
      * Com EFI_CERTIFICATE_HML + EFI_PRIVATE_KEY_HML presentes ele tenta o mTLS.
      * Sem cert/key, retorna `cert_present:false`/`key_present:false` e
        `tls_handshake:"NOT_RUN"` (falha informativa, sem erro).
      * Uma resposta HTTP 401/403 da Efi e sucesso de TRANSPORTE:
        TLS_HANDSHAKE = PASS e AUTH_API = NOT_TESTED (regra ja implementada).
  - O OAuth (Client ID/Secret) fica para EFI-INT-04B, quando o transporte estiver
    provado.
