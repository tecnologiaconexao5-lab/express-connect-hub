## 1. Fluxo de Conclusão da Entrega no APP

### APP_COMPLETION_ENTRYPOINT
App Motorista (Flutter PWA em `prestador.conexaoexpress.com.br`) — projeto externo, não neste repositório.

O App finaliza a entrega via **2 chamadas**:
1. **INSERT em `delivery_proofs`** (REST API Supabase) — dados do POD (foto, recebedor, GPS, etc.)
2. **RPC `f_avancar_etapa_app_motorista`** — advance journey state machine (etapa `servico_finalizado`)

### BACKEND_CALL
- **Tabela primária**: `delivery_proofs` (INSERT direto via REST)
- **Trigger**: `trg_sync_delivery_proof_to_entregas` (AFTER INSERT) → copia para `entregas_protocolo`
- **RPC complementar**: `f_avancar_etapa_app_motorista` → atualiza `alocacoes_escala.status/metadata` + `eventos_oficiais`

## 5. Relacionamentos

### OS_LINK
`entregas_protocolo.ordem_servico_id` → `ordens_servico.id`

**PROBLEMA CRÍTICO**: Apenas **2 de 51** entregas (3.9%) têm `ordem_servico_id` preenchido. 49 entregas são órfãs de OS.

**Causa**: O trigger `f_sync_delivery_proof_to_entregas` copia `ordem_servico_id` de `alocacoes_escala`, mas 134 de 193 alocações (69.4%) NÃO têm `ordem_servico_id` — vieram do App Motorista sem vínculo a OS.

### ALLOCATION_LINK
`entregas_protocolo.alocacao_id` → `alocacoes_escala.id`

**Status**: 51/51 (100%) — sempre preenchido (é a chave de lookup do trigger).

### PROVIDER_LINK

**Status**: 51/51 (100%) — copiado do `alocacoes_escala` pelo trigger.

## 10. Problemas Identificados

### PROBLEMA 1: PodLista não faz JOINs (Raiz do "Entrega #hash")
- **Arquivo**: `src/components/operacao/PodLista.tsx:37-41`
- **Query**: `SELECT * FROM entregas_protocolo ORDER BY data_hora_entrega DESC LIMIT 20`
- **Impacto**: Mostra UUID fragmento em vez de OS number, sem nome de cliente/motorista
- **Correção necessária**: Usar `comprovantesService.listarComprovantes()` (já existe, faz 5 JOINs)

### PROBLEMA 2: 96% das entregas sem ordem_servico_id
- **Dado**: 49/51 entregas com `ordem_servico_id = NULL`
- **Causa**: 134/193 alocações (69%) não têm OS vinculada (App cria alocação direta)
- **Impacto**: Mesmo com JOIN, 96% das entregas não resolvem OS number
- **Correção necessária**: Garantir que `alocacoes_escala.ordem_servico_id` seja preenchido na criação

### PROBLEMA 3: PodLista não usa service layer
- **Arquivo**: `src/components/operacao/PodLista.tsx:37-41`
- **Padrão do código**: queries devem ir via services (ex: `comprovantesService.ts`)
- **Impacto**: Código duplicado, sem enriquecimento, sem paginação

### PROBLEMA 4: receiver_relationship nunca exibido
- **Campo**: `entregas_protocolo.receiver_relationship` (preenchido pelo APP)
- **Dado**: Existe na tabela mas nenhum componente mostra
- **Impacto**: Informação perdida (relação do recebedor com o cliente)

### PROBLEMA 5: Botões "Detalhes" e "Exportar" sem handler
- **Arquivo**: `src/components/operacao/PodLista.tsx:159-163`
- **Impacto**: UI non-functional
