  veiculo.termica = os.carga_refrigerada ? "refrigerado" : (os.veiculo_termica || "seco")

carga_refrigerada=true OU veiculo_termica ∈ {refrigerado, congelado, termico, térmico}
→ operação exige veículo com capacidade térmica.

ordens_servico.carga_refrigerado (boolean) — existe mas menos usado.

2. FONTE OFICIAL VEÍCULO
====================================================================

veiculos.tipo_carga (text) — campo estruturado, valores:
  "seco" (default)
  "refrigerado"
  "congelado"
  "termico" / "térmico"

veiculos.temperatura_min (numeric) — existe, mas OS não tem faixa correspondente.
veiculos.temperatura_max (numeric) — existe, mas OS não tem faixa correspondente.

====================================================================
3. SECO
====================================================================

Veículo seco (tipo_carga = "seco" ou null):
  - NÃO possui capacidade térmica.
  - Operação refrigerada + veículo seco → BLOQUEADO.
  - Operação seca + veículo seco → PERMITIDO.

====================================================================
4. TÉRMICO
====================================================================

Térmico/refrigerado/congelado são classificada como "com capacidade térmica".
Todos são aceitos quando a operação exige refrigerado.

Não foram encontradas restrições que diferenciem térmico de refrigerado
no gate. Conservadorismo: se a operação exige, qualquer capacidade
térmica é aceita.

====================================================================
5. REFRIGERADO
====================================================================

Regras implementadas:

  operação NÃO exige refrigerado
  → veículo seco permitido (não bloqueia).

  operação EXIGE refrigerado
  + veículo possui tipo_carga ∈ {refrigerado, congelado, termico, térmico}
  → PERMITIDO.

  operação EXIGE refrigerado
  + veículo seco/null
  → BLOQUEADO (requisito_refrigerado_nao_atendido).

  operação EXIGE refrigerado
  + veículo sem informação (null/"")
  → BLOQUEADO (não assumir compatível).

====================================================================
6. TEMPERATURA — DEPENDÊNCIA ESTRUTURAL
====================================================================

veiculos: temperatura_min, temperatura_max existem.
ordens_servico: NÃO possui campos de faixa de temperatura.

Conclusão: comparação de faixa NÃO é possível com o schema atual.
Registrado como DEPENDÊNCIA ESTRUTURAL para missão futura.

Exemplo futuro (quando OS tiver min/max):
  OS exige 13°C a 16°C
  Veículo suporta 10°C a 18°C → OK (faixa do veículo cobre a exigida).
  Veículo suporta 18°C a 25°C → BLOQUEADO (faixa não cobre).

====================================================================
7. DADOS AUSENTES
====================================================================

Comportamento do gate:

  OS exige refrigerado + veículo sem tipo_carga (null) → BLOQUEADO.
  Motivo: "não declarar compatível quando não há informação".

  OS sem exigência + qualquer veículo → ELEGÍVEL (fail-open para operação seca).

Ausência de informação NÃO é classificada como "compatível".
É classificada como "incapaz de confirmar compatibilidade" → BLOQUEADO
quando há exigência.

14. PENDÊNCIAS
====================================================================

1. TEMPERATURA — DEPENDÊNCIA ESTRUTURAL:
   OS NÃO possui campos de faixa de temperatura estruturada.
   Comparação min/max exige migration futura para adicionar
   campos na OS (ex: temp_requerida_min, temp_requerida_max).

2. Veículo legado sem tipo_carga preenchido:
   Gate é BLOQUEADO quando há exigência (não assumir compatível).
   Preenchimento do campo é pré-requisito para operações refrigeradas.

3. congrgelado ≠ refrigerado:
   Tratados como equivalentes no gate (ambos têm capacidade térmica).
   Se o sistema precisar distinguir no futuro, separar os conjuntos.
