3) EFEITOS DOS TRIGGERS (mapeados)
==================================================

alocacoes_escala (AFTER INSERT/UPDATE):
  - trg_propagar_financeiro_alocacao (M66): cria OS (id = ordem_servico_id ?? NEW.id),
    numero "ALOC-YYYYMMDD-xxxxxxxx" quando sem OS; grava financeiro_receber (se valor_cliente>0),
    financeiro_pagar, pagamentos_prestadores, composicao_financeira_os; idempotente por os_id.
    Guards: status='cancelada' → skip; valor 0/0 → skip.
  - trg_cancelar_financeiro_alocacao (BEFORE UPDATE): ao cancelar, cancela títulos abertos
    preservando estados protegidos (FIN-01/01.1: pago/parcial/cancelado/recebido).
  - trg_registrar_historico_alocacao (AFTER INSERT/UPDATE): grava historico_alocacoes_escala.
  - trg_evento_alocacao_criada / cancelada / motorista_trocado / recusada /
    prestador_aceitou / operacao_finalizada (AFTER): eventos.
ordens_servico (AFTER INSERT/UPDATE):
  - trg_propagar_financeiro_os (M80): propaga por os_id (valor_cliente/custo_prestador);
  - trg_notificar_os_para_app, trg_evento_os_criada/cancelada/finalizada/status_changed.

Relação M66 × M80: ambos idempotentes por os_id (ON CONFLICT / PERFORM+IF) — sem duplicidade.

5) MÉTODO DE EXECUÇÃO
==================================================

EXECUTION_METHOD=B (UI + cleanup controlado) — recomendado
WHY=
  - BEGIN/ROLLBACK (A) prova triggers/linhas/idempotência, MAS NÃO prova persistência e
    reabertura pela UI (objetivo explícito).
  - C (registros de homologação persistentes) exigiria um conjunto de dados de teste já
    pronto e compatível — não existe (sem tabela VUC).
  - D (não seguro) não se aplica se houver cleanup controlado.
  - B permite: salvar pela UI (sem OS manual) → conferir OS automática + financeiro →
    fechar/reabrir a tela → provar persistência → cleanup pelo id.
  - PRÉ-VALIDAÇÃO recomendada: rodar o mesmo cenário em BEGIN/ROLLBACK (A) antes do B,
    para validar triggers sem gravar.
