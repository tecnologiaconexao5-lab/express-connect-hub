3.2 CONTRATO REAL DA RPC app_s6_criar_prestador

Fonte: 20260829_ag07j18_4_rpc_cadastro_app.sql
  CREATE OR REPLACE FUNCTION app_s6_criar_prestador(
    p_nome_completo TEXT, p_cpf_cnpj TEXT, p_data_nascimento TEXT,
    p_telefone TEXT, p_email TEXT, p_auth_email TEXT, p_senha TEXT,
    p_status TEXT, p_origem TEXT, p_liberado_app BOOLEAN, p_metadata JSONB
  )
  RETURNS JSONB
  LANGUAGE plpgsql
  SECURITY DEFINER
  SET search_path = public

  Comportamento:
    - auth.uid() obrigatorio
    - Normaliza CPF/CNPJ (so digitos)
    - Verifica se auth_user_id ja vinculado --> retorna existente
    - INSERT: status='em_analise', liberado_app=FALSE (hardcoded)
    - origem_cadastro='app_motorista' (hardcoded)
    - p_liberado_app e ACEITO mas IGNORADO

  Grants: REVOKE PUBLIC, REVOKE anon, GRANT authenticated


3.3 IDEMPOTENCIA E SEGURANCA

Idempotencia: OK — Retorna prestador existente se auth_user ja vinculado
Anti-spoof liberado_app: OK — Hardcoded false, ignora parametro
auth.uid() obrigatorio: OK — SECURITY DEFINER + check
Dedup por CPF/CNPJ: OK — Normaliza e verifica antes de INSERT
Retry/fallback: FALHA — Sem retry em caso de falha
Usuario orfao: ALERTA — Se signUp OK mas RPC falha, auth.user existe sem prestador
Dados reais no Bridge: FALHA — Bridge gera NOME/CIDADE/VEICULO mockados


3.4 PROBLEMAS DO FLUXO

P1: Bridge usa polling (so roda ao abrir Pipeline), nao event-driven — GRAVIDADE ALTA
P2: Bridge gera dados MOCKADOS (nome, cidade, veiculo) em vez de ler do prestador real — GRAVIDADE ALTA
P3: Sem trigger automatico no INSERT de prestadores para criar candidato no pipeline — GRAVIDADE ALTA
P4: Usuario orfao possivel (auth.user sem prestador) — GRAVIDADE MEDIA
P5: RPC nao cria veiculo nem documentos — GRAVIDADE MEDIA
P6: Sem Edge Function de sincronizacao — GRAVIDADE MEDIA
