# CAUSA DO DESLOCAMENTO -3h (TIMEZONE) — EVIDÊNCIA DE CÓDIGO
--------------------------------------------------------------------------------
Fluxo no App (não alterado; análise de código):
- tracking_session_service.dart:139   → final now = DateTime.now();
- tracking_session_service.dart:148   → capturedAt: now
- real_tracking_service.dart:159      → capturedAt ??= DateTime.now();
- real_tracking_service.dart:186      → createdAt: capturedAt
- tracking_point.dart:110             → 'p_captured_at': createdAt.toIso8601String()

PROBLEMA:
- Em Flutter, DateTime.now() retorna hora LOCAL do dispositivo (Brasil = UTC-3, BRT).
- Dart's toIso8601String() para um DateTime LOCAL NÃO anexa sufixo de offset nem 'Z'.
  Ex.: "2026-08-15T07:56:15.558" (sem timezone).
- O Postgres/Supabase interpreta string timestamp SEM timezone como UTC
  (servidor configurado em UTC — confirmado via SHOW timezone).
- Resultado: hora local 07:56 (BRT) = 10:56 UTC real, mas gravada como 07:56Z
  → captured_at fica exatamente -3h (BRT) no passado.

CONFIRMAÇÃO BANCO:
- SHOW timezone → UTC.
- captured_at sem DEFAULT (vem 100% do payload do App), sem trigger que reescreva.
- created_at DEFAULT now() (UTC do servidor, correto).
- diff created_at − captured_at da posição nova = 10800.59s = 3h exatas.
