RELATÓRIO TMS-S04C.1 — HOTFIX DO CRASH DO RELATÓRIO DE FATURAMENTO
Data: 22/08/2026
Status: CORRIGIDO + VALIDADO (tsc/vitest/build + teste de montagem)

====================================================================
1. CAUSA EXATA
====================================================================

Temporal Dead Zone (TDZ): no componente RelatorioFaturamentoCliente, as
constantes `hoje` e `primeiroDiaMes` eram declaradas DEPOIS dos novos
useState da visão individual (adicionados na TMS-S04C). Os inicializadores
`useState(obterDataLocalFormatada(primeiroDiaMes))` e
`useState(obterDataLocalFormatada(hoje))` executavam ANTES da declaração
das const → ReferenceError: "Cannot access 'primeiroDiaMes' before
initialization" no primeiro render.

====================================================================
2. LINHA / TRECHO RESPONSÁVEL
====================================================================

Antes da correção (arquivo RelatorioFaturamentoCliente.tsx):
  ...useState(filtroAberto)...
  const [dataIniInd, setDataIniInd] = useState(obterDataLocalFormatada(primeiroDiaMes));  ← uso antes da decl
  const [dataFimInd, setDataFimInd] = useState(obterDataLocalFormatada(hoje));            ← uso antes da decl
  ...
  const hoje = new Date();                                                                 ← declaração tardia
  const primeiroDiaMes = new Date(hoje.getFullYear(), hoje.getMonth(), 1);                ← declaração tardia

O navegador apontou: RelatorioFaturamentoCliente.tsx:93:72.

====================================================================
3. POR QUE TYPESCRIPT/BUILD NÃO DETECTARAM
====================================================================

O TS valida TIPOS (as const estão tipadas como Date e o uso é válido no
escopo), mas a ordem de EXECUÇÃO em runtime só é detectada em execução.
O eslint do projeto não possui a regra `no-use-before-define` habilitada
para esse caso, e o vitest não renderizava o componente (os testes da
S04C validavam o PDF/serviços, não o mount do componente). Por isso tsc,
vitest 507/507 e build passaram sem detectar o TDZ.
