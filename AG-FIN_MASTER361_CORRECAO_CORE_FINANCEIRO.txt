SEÇÃO 3 — CAUSA RAIZ DE CADA BUG
═══════════════════════════════════════════════════════════════════════════════

  P0-1: ContasPagar.tsx usa `r.valor_bruto || r.valor` para `valorOriginal`.
        A coluna `valor` é a canônica (valor líquido/real do título).
        `valor_bruto` pode ser diferente quando há adicional/desconto.
        Causa: código original priorizava campo legado.

  P0-2: ContasPagar.tsx soma `status === "paga"` do array financeiro_receber.
        Status "paga" é um flag binário que pode ser setado incorretamente
        por triggers ou UI. Baixas reais ficam em financeiro_baixas.
        Causa: confusão entre "título quitado" e "movimentação bancária".

  P0-3: FluxoCaixaEnterprise.tsx define `saldoInicialConfigurado = false`
        e `setSaldoInicialConfigurado(false)` hardcoded. Nunca lê
        contas_financeiras.saldo_inicial.
        Causa: código original era placeholder sem integração ao banco.

  P1-3: ModalBaixaPagar não tem parâmetro `contaFinanceiraId`.
        RPC antigo aceitava apenas `conta_financeira` (TEXT — nome).
        Sem UUID, não há vínculo real à conta financeira.
        Causa: migration anterior adicionou coluna mas não atualizou o RPC.

  P2-8: `baixarPagavel()` em pagarService.ts não aceita `contaFinanceiraId`.
        Chama RPC com 10 parâmetros (antigo), sem o UUID da conta.
        Causa: assinatura do service não foi atualizada quando o campo foi
        adicionado à tabela.

  P0-4: FluxoCaixa lê `contas_financeiras` mas trata null como zero sem
        warning. Usuário vê R$ 0.00 sem saber se é real ou não configurado.
        Causa: falta de tratamento adequado de null/undefined.

SEÇÃO 5 — REGRAS CANÔNICAS ESTABELECIDAS
═══════════════════════════════════════════════════════════════════════════════

  REGRA 1 — VALOR CANÔNICO:
    fonte = financeiro_pagar.valor (ou financeiro_receber.valor)
    UI deve exibir: r.valor || r.valor_bruto
    RPC usa: valor (canonical)

  REGRA 2 — SALDO REAL:
    SALDO = saldo_inicial + ENTRADAS (baixas) - SAÍDAS (baixas) ± TRANSFERÊNCIAS
    fonte saldo_inicial = contas_financeiras.saldo_inicial (ativa=true)
    fonte entradas/saídas = financeiro_baixas (estornada=false)
    NÃO usa: status de financeiro_receber/financeiro_pagar

  REGRA 3 — BAIXA = MOVIMENTAÇÃO:
    financeiro_baixas = livro-razão de cada centavo movimentado
    financeiro_receber/pagar = apenas status (aberto/parcial/pago)
    trigger M66/M80 cria baixas automaticamente

  REGRA 4 — TRANSFERÊNCIA = OPERAÇÃO ATÔMICA:
    Uma transferência = UMA operação contábil (débito + crédito)
    NÃO = 2 UPDATEs independentes
    Tabela financeiro_transferencias rastreia cada operação

  REGRA 5 — PREVISTO = PREDIÇÃO:
    Filtro "Previsto" pode incluir títulos "Sem conta definida"
   isenão interfere no cálculo de realizado (baixas)

SEÇÃO 12 — FLUXO FINANCEIRO CORRIGIDO
═══════════════════════════════════════════════════════════════════════════════

  TÍTULO CRIADO ( financeiro_pagar / financeiro_receber )
       │
       ▼
  SALDO INICIAL ( contas_financeiras.saldo_inicial )
       │
       ▼
  BAIXA REGISTRADA ( financeiro_baixas )
  │   ├── titulo_tabela = 'financeiro_pagar' ou 'financeiro_receber'
  │   ├── valor_baixado = valor real movimentado
  │   ├── conta_financeira_id = UUID da conta (NOVO)
  │   ├── estornada = false
  │   └── data_baixa = data efetiva
  │
  ▼
  TÍTULO ATUALIZADO ( status = parcial / pago )
       │
       ▼
  CONTA FINANCEIRA ATUALIZADA ( contas_financeiras.saldo )
       │
       ├── ENTRADA: saldo += valor_baixado (receber)
       └── SAÍDA: saldo -= valor_baixado (pagar)
       │
       ▼
  TESOURARIA ( ContasBancarias )
  │   ├── Saldo real = saldo_inicial + baixas
  │   ├── Transferência = 1 RPC atômico
  │   └── Histórico = financeiro_transferencias
  │
       ▼
  FLUXO DE CAIXA ( FluxoCaixaEnterprise )
  │   ├── Saldo inicial do DB (não hardcoded)
  │   ├── Realizado = baixas (não status)
  │   └── Previsto inclui "Sem conta definida"
  │
       ▼
  DRE / INDICADORES ( dados derivados do realizado )
       │
       ▼

SEÇÃO 14 — RISCOS REMANESCENTES
═══════════════════════════════════════════════════════════════════════════════

  1. MIGRAÇÃO NÃO APLICADA — A migration 20260903_fin_master361_core_financeiro.sql
     ainda não foi executada no Supabase. O RPC antigo (10 params) continua
     ativo. As UIs já passam o 11º param, mas o RPC ignora (DEFAULT NULL).
     Risco: baixas registradas SEM conta_financeira_id até aplicação.
     Mitigação: aplicar migration em janela de manutenção.

  2. DUPLA ESCRITA FINANCEIRA — trigger M66 (alocacoes_escala → financeiro)
     + trigger M80 (ordens_servico → financeiro) podem criar baixas
     concorrentes. já mitigado por UNIQUE(os_id) e ON CONFLICT.
     Risco: baixas duplicadas em race condition (já existente, não regressivo).

  3. VALOR BRUTO vs VALOR — Alguns títulos podem ter valor_bruto diferente
     de valor. A correção P0-1 prioriza valor. Se algum título antigo tem
     valor=NULL e valor_bruto preenchido, a UI mostraria o bruto.
     Risco: baixo (fallback para valor_bruto mantido).

  4. SALDO INICIAL STATIC — saldo_inicial em contas_financeiras é fixo.
     Se o saldo real mudou (por erros anteriores), há divergência.
     Risco: baixo (exige reconciliação manual).
