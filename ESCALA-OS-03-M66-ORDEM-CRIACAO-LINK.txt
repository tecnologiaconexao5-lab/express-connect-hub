ROOT CAUSE (confirmada)
==================================================

Em f_trg_propagar_financeiro_alocacao (M66):
  1. UPDATE alocacoes_escala.ordem_servico_id = v_os_id   (ANTES)
  2. INSERT ordens_servico (id = v_os_id)                 (DEPOIS)
A FK `alocacoes_escala_ordem_servico_id_fkey` é IMEDIATA (condeferrable=false).
Quando a OS ainda não existe, o passo 1 viola a FK. Historicamente o erro era
suprimido (THEN NULL) → ordem_servico_id ficava NULL (134 alocações). Após E2E-05
(propaga), editar uma alocação sem OS FALHA.

==================================================
CORREÇÃO
==================================================

Reordenado o M66: quando ordem_servico_id IS NULL:
  1. v_os_id = NEW.id (mecanismo canônico);
  2. INSERT/upsert da OS PRIMEIRO (ON CONFLICT (id) DO UPDATE — idempotente);
  3. SOMENTE DEPOIS UPDATE alocacoes_escala.ordem_servico_id = v_os_id;
  4. propagação financeira normal (receber/pagar/pagamentos/composição).

Migration: supabase/migrations/20260922000007_escala_os_03_m66_ordem_criacao_link.sql
Rollback:  supabase/migrations/20260922000008_escala_os_03_rollback.sql
  (rollback = definição EXATA anterior, com o link UPDATE antes do INSERT da OS)

atualizarAlocacao NÃO foi alterado (autoridade única no backend = M66).

Preservado: ON CONFLICT (id); EXCEPTION WHEN OTHERS THEN RAISE (E2E-05);
guardas FIN-01; cancelamento E2E-03; OS não obrigatória OS-01.
