3. FLUXO APP → TMS (RASREAMENTO COMPLETO)
==============================================================================

3.1 FLUXO ATUAL (ETAPA POR ETAPA)
------------------------------------

ETAPA 1: Motorista acessa /cadastro-prestador
  → CadastroPrestador.tsx (wizard 5 etapas)
  → StepPersonal: nome, CPF, selfie, CNH
  → StepVehicle: tipo, modelo, placa, ano, capacidade, fotos
  → StepDocuments: CRLV, comprovante residencia, PIX, banco
  → StepAvailability: regioes, tipo carga, tipo viagem
  → StepSignature: LGPD, contrato, responsabilidade, assinatura

ETAPA 2: Submit → criarCandidatoService.criar()
  → INSERT em recrutamento_candidatos
  → stage: 'interesse_confirmado'
  → status: 'interessado'
  → canal_captacao: 'onboarding_app'
  → DADOS NAO VAO PARA prestadores (ainda)

ETAPA 3: Processamento IA (processarCandidato)
  → centralIaService → roboRecrutamentoService
  → Analise de perfil, score, documentos
  → Atualiza stage/status em recrutamento_candidatos

ETAPA 4: Bridge Kanban (buscarECadastrarAppPrestadores)
  → enterpriseKanbanService.ts
  → Busca prestadores com origem_cadastro='app_motorista'
  → Para cada prestador NOVO (sem对应 em recrutamento_candidatos):
    → INSERT em recrutamento_candidatos
    → stage: 'interesse_confirmado'
  → PARA PRESTADORES JA EXISTENTES:
    → NAO duplica

ETAPA 5: Conversao (conversaoCandidatoService)
  → sincronizarComOperacao(candidato)
  → Gate documental: CNH + CRLV + Comprovante + Foto Veiculo
  → Cria em recrutamento_prestadores (tabela oficial recrutamento)
  → Atualiza recrutamento_candidatos: prestador_id, status='ativo'
  → Chama recrutamentoIntegracao.ativarPrestador()

ETAPA 6: Ativacao (recrutamentoIntegracao.ts)
  → checarDuplicidade() por CPF, email, telefone
  → SE duplicado: atualiza prestador existente
  → SE novo: INSERT em prestadores
    → status: 'ativo'
    → liberado_app: false (fail-closed!)
    → origem_cadastro: 'recrutamento'
  → Migracao de documentos: vincularDocumentoCandidatoAPrestador()

ETAPA 7: Liberacao App
  → conversaoCandidatoService.sincronizarComOperacao()
  → liberado_app = statusOperacional === 'ativo'
  → statusOperacional depende de:
    - status prestador = 'ativo'
    - liberado_app = true (gate duplo)
    - documentos_prestadores validos
    - CNH validade nao vencida

4.4 FLUXO DOCUMENTO: APP → ADMIN
------------------------------------

1. Motorista faz upload no onboarding
   → Documentos permanecem no state local (onboardingStore)
   → NAO sao uploadados para Storage no onboarding!

2. Apos criacao do candidato (recrutamento_candidatos)
   → IA analisa documentos (se configurado)
   → Documentos armazenados no JSONB 'documentos' do candidato

3. Na conversao para prestador:
   → vincularDocumentoCandidatoAPrestador()
   → Migra de candidato_id → prestador_id em documentos_prestadores
   → Status: 'valido', origem: 'recrutamento_migrado'

4. No TMS Admin:
   → PrestadorDetalhe.tsx carrega de documentos_prestadores
   → Upload manual via Storage bucket 'documentos_prestadores'
   → Upload admite: CNH Frente, CNH Verso, CRLV, Comprovante, Contrato, etc.

   - selfieUrl, cnhUrl, crlvUrl, comprovanteUrl
   - Mas NAO faz upload para Storage durante o wizard
   - Apenas salva URLs no onboardingStore (state local)
   - URLs podem ser relativas ou blob URLs (não persistentes)

   → Ao submeter, criarCandidatoService NAO envia URLs de arquivo
   → Documentos NAO chegam a documentos_prestadores automaticamente
   → Gap: motorista envia documentos mas Admin nao ve

8.4 AUTH (SUPABASE AUTH)
---------------------------

LOGIN PRESTADOR:
  → Prestador acessa /portal-prestador
  → obterPrestadorPorAuth() → RPC f_obter_prestador_por_auth()
  → Busca auth.uid() em prestadores.auth_user_id
  → Se nao encontrar: erro "Nenhum prestador vinculado"

RESET DE SENHA:
  → AuthContext.resetPassword(email)
  → supabase.auth.resetPasswordForEmail()
  → Rota /reset-password funcional
  → Audita em auth_eventos_auditoria

LOGOUT:
  → AuthContext.logout()
  → supabase.auth.signOut()
  → Limpa state + sessionStorage

SESSAO:
  → onAuthStateChange() monitora
  → INITIAL_SESSION + SIGNED_IN handler
  → Safety timer 6s para fallback
