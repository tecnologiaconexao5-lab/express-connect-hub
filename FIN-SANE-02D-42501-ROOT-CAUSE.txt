4. ANALISE DAS HIPOTESES
============================================================

HIPOTESE 1: "supabase_admin perdeu permissao no schema"
   STATUS: REFUTADO.
   - supabase_admin e superuser (prova A).
   - Superuser nao pode receber "permission denied for schema".
   - GRANTs para supabase_admin em tentativas anteriores nao resolveram (consistente com essa refutacao).

HIPOTESE 2: "postgres executa o INSERT e falha por falta de permissao"
   STATUS: REFUTADO.
   - postgres e OWNER do schema e da tabela (prova C).
   - Owner tem implicitamente USAGE/CREATE no proprio schema e ALL na propria tabela.
   - Se postgres executasse o INSERT, nao haveria 42501.

HIPOTESE 3: "O INSERT final e executado por um role NAO-superuser diferente de postgres"
   STATUS: FORTEMENTE SUSTENTADO (nao diretamente provado por inspecao, mas e a unica explicacao consistente).
   - O erro 42501 so ocorre para role sem USAGE no schema.
   - postgres (owner) e supabase_admin (superuser) nao podem gerar esse erro.
   - O INSERT nao esta nos logs (prova F), sugerindo role com log_statement=none (interno).
   - O CLI mantem multiplas conexoes com roles diferentes (postgres para migrations, supabase_admin para servicos, supabase_auth_admin, supabase_storage_admin).
   - Conclusao: o pool de conexoes do CLI usou uma conexao com role errado para o INSERT final de tracking.

HIPOTESE 4: "Perda de SET ROLE postgres (pool idle timeout)"
   STATUS: FORTEMENTE SUSTENTADO por evidencia externa.
   - PR supabase/cli#5895 (merged 2026-07-21) descreve exatamente esse mecanismo:
     "The TS role step-down was lost mid-command... PgClient.make leaves node-postgres' default 10s idle timeout — during the minutes-long shadow diff the pool silently reaped and redialed the stepped-down connection, so the final CREATE SCHEMA IF NOT EXISTS supabase_migrations executed as the bare login role (42501)."
   - O fix foi implementado para db pull, mas o mesmo mecanismo de pool/role-step-down pode afetar o path de supabase start.
   - A duracao do pipeline de 80+ migrations (varios minutos) e consistente com idle timeout de conexao.
   - NENHUM comando SET ROLE aparece nos logs (prova F parcial — log_statement pode nao capturar), mas o sintoma e identico.
