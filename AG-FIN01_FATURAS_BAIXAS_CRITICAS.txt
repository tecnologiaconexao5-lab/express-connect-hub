SEÇÃO 3 — BUGS CRÍTICOS ENCONTRADOS (3 itens)
═══════════════════════════════════════════════════════════════════════════════

BUG-1 [CRÍTICO] — atulizarFatura() tenta atualizar coluna "descricao" que NÃO EXISTE
  Localização: faturaService.ts:322, 1018, 1021
  Causa:       A interface Fatura.ts:25 declara `descricao: string | null` como propriedade.
               A função atualizarFatura() aceita Pick<..., "descricao"> e gera
               `UPDATE faturas SET descricao = ... WHERE id = ...`.
               Porém a tabela faturas NÃO TEM coluna "descricao" — o campo é JSONB
               armazenado em metadata.descricao.
  Impacto:     Qualquer tentativa de editar descrição de fatura (manual ou automática)
               GERA ERRO DO SUPABASE: 'column "descricao" of relation "faturas" does not exist'
               Validação confirmada: UPDATE faturas SET descricao = NULL WHERE false → ERRO
  Correção:    Em atualizarFatura(), NÃO incluir descricao no payload SQL.
               Em vez disso, gravar em metadata.descricao (já faz parcialmente
               na linha 336 mas DELETA descricao do payload na linha 339 — bypass não funciona
               porque o payload já incluiu descricao via ...updates na linha 329).
  Status:      PENDENTE CORREÇÃO

BUG-2 [CRÍTICO] — buscarClienteParaFatura() query SELECT "endereco" de clientes (coluna não existe)
  Localização: faturaService.ts:689
  Causa:       A query seleciona `clientes.endereco` mas a tabela clientes não tem
               essa coluna. Colunas de endereço em clientes: logradouro, numero,
               complemento, bairro, cidade, uf, cep.
  Impacto:     A query Supabase retorna erro silencioso. A função continua porque
               a parallela buscarEnderecoPrincipalCliente() é separada, mas o
               enderecoBase = data.endereco será undefined.
               Para clientes sem registros em enderecos_clientes (como CALVO),
               o endereço fica VAZIO no PDF.
  Correção:    Substituir `endereco` por `logradouro, numero, complemento, bairro` na query
               e montar o enderecoBase concatenando esses campos.
  Status:      PENDENTE CORREÇÃO

BUG-3 [ALTO] — contas_financeiras_config não existe — buscarContasBancariasConfig() retorna []
  Localização: configFinanceiraService.ts:163
  Causa:       A função lê de configuracoes_sistema WHERE chave = 'contas_financeiras_config'.
               Esta chave NÃO existe no banco. A tabela real de contas bancárias
               é contas_financeiras (com colunas: banco, agencia, numero_conta, etc).
  Impacto:     FaturaManualDialog nunca exibe contas bancárias configuradas.
               O dropdown "Conta para recebimento" sempre mostra mensagem de fallback.
               O PDF usa a conta padrão da empresa (buscarDadosEmpresaParaFatura).
  Correção:    Substituir a leitura de configuracoes_sistema por consulta direta
               a contas_financeiras WHERE ativa = true.
  Status:      PENDENTE CORREÇÃO

6.1 RPC f_registrar_baixa_financeira
  Assinatura: (p_titulo_tabela, p_titulo_id, p_valor_baixado, p_data_baixa,
               p_forma_pagamento, p_conta_financeira, p_referencia_bancaria,
               p_observacao, p_usuario_id, p_usuario_nome)
  NÃO aceita p_valor_original — o RPC DERIVA o valor_original do registro:
    SELECT valor INTO v_valor_original FROM financeiro_pagar WHERE id = p_titulo_id
  → financeiro_pagar.valor pode ser NULL (verificado: 1 de 3 registros com valor=NULL)
  → Se valor=NULL, a baixa falharia com saldo NULL

6.2 financeiro_baixas
  Tabela: financeiro_baixas
  Coluna valor_original: NOT NULL (confirmado)
  A INSERT é feita pelo RPC com v_valor_original derivado do registro
  → Frontend NÃO precisa enviar valor_original (correto)
  → financeiro_baixas ZERO registros (nenhuma baixa registrada)

6.3 financeiro_pagar —(valor pode ser NULL
  3 registros auditados:
    id: 26e05ffe... | valor: NULL  | status: "a vencer"  ← PERIGOSO
    id: 05d87f10... | valor: 850   | status: "aberto"
    id: b4292aa5... | valor: 850   | status: "aberto"
  O registro com valor=NULL tem status "a vencer" — se alguém tentar baixar,
  o RPC falhará porque v_valor_original será NULL.
