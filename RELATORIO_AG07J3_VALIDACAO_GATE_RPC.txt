5. GAPS IDENTIFICADOS
======================

GAP J.3-1: REVOKE ALL AUSENTE NO OVERLOAD 4-PARAM (P1)
  Overload 0-param tem: REVOKE ALL FROM PUBLIC, anon ✅
  Overload 4-param NÃO tem: herda permissões padrão do PostgreSQL ⚠️
  Impacto: anon podría executar a RPC 4-param
  Correção: adicionar REVOKE ALL antes do GRANT

GAP J.3-2: OWNERSHIP CHECK REMOVIDO (P1)
  M133-D.2 verificava: auth.uid() = prestadores.auth_user_id
  AG-07F 4-param: aceita qualquer p_prestador_id sem verificar ownership
  Impacto: qualquer authenticated pode consultar operações de qualquer prestador
  Correção: adicionar WHERE auth.uid() = (SELECT auth_user_id FROM prestadores WHERE id = p_prestador_id)

GAP J.3-3: M133-D.2 NÃO SUBSTITUÍDO (P1)
  M133-D.2 (p_auth_user_id UUID) continua ativo no DB
  Se App chama M133-D.2, gate AG-07F NÃO é aplicado
  Impacto: bypass do gate se App usar assinatura antiga
  Correção: DROP M133-D.2 após confirmar App migrou para nova assinatura

GAP J.3-4: CANCELADA/RECUSADA NÃO EXCLUÍDA (P2)
  M133-D.2 excluía: IS DISTINCT FROM 'cancelada'/'recusada'
  AG-07F 4-param NÃO exclui (usa p_status caller-controlled)
  Impacto: operações canceladas podem aparecer no App
  Correção: adicionar filtro default ou documentar comportamento

GAP J.3-5: FONTE DE DADOS MUDOU (P2)
  M133-D.2: alocacoes_escala direta (30 campos manuais)
  AG-07F 4-param: vw_app_motorista_operacoes (107 campos da view)
  Impacto: row shape diferente, paradas podem não estar incluídas
  Correção: validar com time Flutter se view tem todos os campos necessários
