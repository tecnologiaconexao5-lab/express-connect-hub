1. CAUSA
====================================================================

AG-07I-B1 criou equivalências globais baseadas em opinião:
  passeio ↔ outro
  van ↔ kombi

Nenhuma tinha evidência contratual no código existente.

====================================================================
2. RISCO DE PASSEIO ↔ OUTRO
====================================================================

"outro" é uma categoria genérica que o App produz para qualquer
veículo sem mapeamento (Carro de Passeio, veículos novos, etc.).

Se a OS exigir "passeio" e o prestador tiver "outro" (que pode ser
um utilitário, uma van velha, etc.), o gate anterior aceitava.
Isso é inseguro.

====================================================================
3. MAPPING FINAL CARRO DE PASSEIO
====================================================================

App _tipoVeiculoTms (register_screen.dart:729):
  ANTES: default → 'outro'
  DEPOIS: case 'Carro de Passeio' → 'passeio'

Correção segura porque:
  - TMS possui "passeio" como tipo oficial (TIPO_VEICULO_LABEL)
  - Nenhum consumidor depende de "Carro de Passeio" → "outro"
  - Dados legados como "outro" permanecem "outro" (não convertidos)

====================================================================
4. REGRA FINAL DE "OUTRO"
====================================================================

outro × outro → ✅ COMPATÍVEL
outro × passeio → ❌ INCOMPATÍVEL
outro × truck/fiorino/van/etc. → ❌ INCOMPATÍVEL

"outro" NÃO é wildcard. Só é compatível consigo mesmo.

====================================================================
5. EVIDÊNCIA VAN/KOMBI
====================================================================

TMS trata van e kombi como tipos DISTINTOS:

tiposVeiculo.ts:
  kombi: { pesoMax: 1100, cubagemMax: 4.0 }
  van: specs diferentes (definidos separadamente)

cargaService.ts:
  kombi: { pesoMin: 121, pesoMax: 1000, cubagemMax: 5 }

validarAlocacaoEscala.ts:
  Lista van e kombi como tipos separados.

App _tipoVeiculoTms:
  Kombi e Van são mesclados para 'van' — mas isso é escolha do App,
  não uma equivalência contratual do TMS.

Conclusão: NÃO existe evidência de que van e kombi são equivalentes.
O App os mescla por conveniência, mas o TMS os trata separadamente.

Decisão: REMOVER equivalência van ↔ kombi.

====================================================================
6. EQUIVALÊNCIAS FINAIS PERMITIDAS
====================================================================

NENHUMA.

Todos os tipos são match exato:
  moto × moto → OK
  passeio × passeio → OK
  fiorino × fiorino → OK
  kangoo × kangoo → OK
  van × van → OK
  kombi × kombi → OK
  hr × hr → OK
  vuc × vuc → OK
  toco × toco → OK
  truck × truck → OK
  carreta × carreta → OK

Qualquer combinação de tipos DIFERENTES → INCOMPATÍVEL.
