SEÇÃO 3 — CORREÇÃO B-1: atualizarFatura()
═══════════════════════════════════════════════════════════════════════════════
Arquivo: src/services/financeiro/faturaService.ts

Problema:
  A assinatura incluía "descricao" no Pick<> e o spread ...updates colocava
  descricao no payload SQL antes do delete, causando:
    ERROR: column "descricao" of relation "faturas" does not exist

Correção:
  const { modelo: _modeloUpd, descricao: _descricaoUpd, ...sqlUpdates } = updates;
  payload = { ...sqlUpdates, atualizado_em: ... };
  if (_modeloUpd !== undefined || _descricaoUpd !== undefined) {
    payload.metadata = { ...metadataBase, modelo: ..., descricao: ... };
  }

Resultado: descricao NUNCA entra no payload SQL. Sempre armazenada em metadata.

SEÇÃO 4 — CORREÇÃO B-1b: atualizarFaturaManual()
═══════════════════════════════════════════════════════════════════════════════
Arquivo: src/services/financeiro/faturaService.ts (linha ~1010)

Problema:
  upd.descricao era passado para atualizarFatura() que agora extrai corretamente.
  Adicionalmente, metadata.descricao não era atualizado nesta função.

  (linha adicionada antes do update de metadata)
  Removido "descricao" do Pick<> do upd (não é coluna SQL).
