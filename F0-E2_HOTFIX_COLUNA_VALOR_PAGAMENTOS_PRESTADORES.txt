--------------------------------------------------------------------------------
2. "valor" EXISTE OU NÃO?
--------------------------------------------------------------------------------
NAO. `valor` NÃO existe em public.pagamentos_prestadores.

  * A coluna `valor` existe APENAS na tabela legada `pagamento_prestadores`
    (singular, 6 colunas: id, os_id, prestador_id, valor, status, created_at).
  * A coluna `valor` também aparece no migration file
    20260510090000_baseline_external_tables.sql (linha 159:
    "valor numeric(10,2) DEFAULT 0"), que NÃO reflete o schema vivo.
  * Portanto, o erro de produção "Could not find the 'valor' column of
    'pagamentos_prestadores' in the schema cache" é CORRETO e consistente:
    o PostgREST rejeita a escrita de uma coluna que não existe.

--------------------------------------------------------------------------------
3. POR QUE F0-E ANTERIOR DIVERGIOU
--------------------------------------------------------------------------------
F0-E validou o contrato contra o migration file
20260510090000_baseline_external_tables.sql (que declara `valor` na tabela
plural), em vez de consultar o schema VIVO via information_schema.columns.

Resultado: o teste F0-E listava `valor` em COLUNAS_REAIS e o payload de
criarPagamento()/criarFechamento()/atualizarFechamento() gravava `valor`.
Como o migration file (intenção) divergiu do schema real de produção
(drift de migração — a tabela viva tem 45 colunas SEM `valor`), a escrita
falhava em produção com o erro do schema cache do PostgREST.

O F0-E2 corrige a fonte de verdade: information_schema VIVO (auditoria
read-only executada nesta missão) em vez de migration file.
