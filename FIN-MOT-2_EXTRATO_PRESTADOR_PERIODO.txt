## RESUMO

Na tela real **Financeiro → Pagamentos → Pag. Prestadores → Fechamentos e Pagamentos**
foi adicionado o botão **"Gerar Extrato do Período"**, que abre um painel com:

- **Prestador** (obrigatório — cadastro real de `prestadores`);
- **Data inicial** e **Data final** (padrão = mês atual);
- **Cliente** (opcional — "Todos os clientes" ou um cliente específico por ID);

e gera o extrato **em memória**, SEM criar fechamento nem registrar em
`pagamentos_prestadores`. O extrato é exibido no **mesmo modal reutilizado** e o
PDF é gerado pelo **mesmo gerador reutilizado** (`generateExtratoPrestadorPDF`),
garantindo **TMS = PDF**.

## C. REGRA DE DEDUPLICAÇÃO

**Chave utilizada: `ordens_servico.id`** (identificador único de cada OS/operação).

- Cada OS do prestador no período é carregada uma única vez via
  `supabase.from('ordens_servico').eq('prestador_id', …)`.
- Não se busca escala/alocação, item de pagamento ou movimento financeiro como
  fonte de crédito de produção — a produção vem exclusivamente das **OS**.
- `pagamentos_prestadores_itens` é usado APENAS para marcar **"Já fechada"**
  (leitura), nunca para listar uma segunda linha de crédito.
- Resultado: a mesma OS aparece no máximo 1 vez, sem crédito duplicado mesmo
  que exista fechamento, item ou movimento ligado a ela.

## D. FONTES DE DADOS

| Necessidade | Fonte real | Como |
|-------------|-----------|------|
| Operações / produção | `ordens_servico` | `prestador_id` + status finalizada/concluida + período, filtro por `cliente_id` |
| Cliente | `ordens_servico.cliente_id` / `cliente` | ref. real por ID (não texto) |
| Valor base do prestador | `ordens_servico.custo_prestador` | valor REAL do prestador (não do cliente) |
| KM / adicionais | `ordens_servico.km_total`, `ordens_servico.adicionais` | exibição + soma |
| Pedágio | `ordens_servico.pedagio` | soma |
| Descontos | `ordens_servico.descontos` + débitos de `pagamentos_prestadores` | soma |
| Adiantamentos | `pagamentos_prestadores` (natureza débito, tipo adiantamento/vale) | no período |
| Combustível | `pagamentos_prestadores` (débito, tipo combustível/abastec.) | quando existir; senão 0 |
| Marcação "já fechada" | `pagamentos_prestadores_itens` ↔ `pagamentos_prestadores` | leitura p/ flag |
| Prestador | `prestadores` | cadastro real (seletor + dados) |

## E. O QUE FALTA (pendências reais)

1. **Combustível integrado ao extrato: NÃO (por padrão desta missão).** Há leitura
   de movimentos débito de combustível em `pagamentos_prestadores`, mas ainda não
   existe a integração completa de autorização de abastecimento/fornecedores (missão
   futura). Se NÃO houver movimento real, o documento mostra **zero/ausência** — nada
   é inventado. Registrar: **Combustível integrado ao extrato: NÃO (aguarda missão
   futura de abastecimento)**.
2. **Reembolsos e Bônus: 0 nesta versão consultiva.** Não há coluna direta de
   reembolso/bônus por OS na fonte de produção usada; não foram inventados. Em
   fechamentos existentes (FIN-MOT-1H2) eles vêm dos valores gravados do fechamento.
3. **Nome do cliente por OS na listagem consultiva:** a OS guarda `cliente_id`/`cliente`
   (UUID); resolver para o nome exigiria join adicional. O modal do período usa a coluna
   direta; se a OS não expuser o nome, exibe "—". (Sem inventar.)
4. **Prova visual** (exigida pelo enunciado): subir o TMS e navegar até o fluxo. Depende
   do ambiente do usuário — não declarado como homologado visualmente.
