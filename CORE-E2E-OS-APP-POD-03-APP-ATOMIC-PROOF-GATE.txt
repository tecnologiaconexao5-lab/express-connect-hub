3 — CONFIRMACAO REAL DO INSERT
==================================================

CREATE_RETURN_TYPE=
  Future<PersistResult>
  PersistResult contem: outcome (PersistOutcome), error, wasAlreadyPresent

INSERT_ERROR_HANDLING=
  DeliveryProofRepository.create() tratAMENTO INTERNO completo:
  - Column error → retry sem campos opcionais
  - FK error → PersistResult.failed (nao enfileira)
  - Auth error → queue offline ou failed
  - Duplicate → PersistResult.remote(wasAlreadyPresent: true)
  - Network/other → queue offline (PersistResult.queuedOffline)
  - Queue fail → PersistResult.failed

INSERT_SUCCESS_CONFIRMATION=
  PersistResult.remote() quando INSERT OK
  PersistResult.remote(wasAlreadyPresent: true) quando duplicata/idempotente
  PersistResult.queuedOffline() quando enfileirado offline

NOTA: create() NUNCA throw. Todas as excecoes sao tratadas internamente.
O try-catch anterior era 100% dead code.

  1. ID estavel: const Uuid().v5(Uuid.NAMESPACE_DNS, 'pod_$opId')
     Mesmo ID gerado para mesma operacao

  2. Idempotency key: 'pod_$opId'
     DeliveryProofRepository._isAlreadyCached() verifica:
     - cache local: p.id == proof.id || p.idempotencyKey == proof.idempotencyKey
     - se ja no cache: retorna PersistResult.remote(wasAlreadyPresent: true)

  3. Duplicate error handling (delivery_proof_repository.dart:78-85):
     Se INSERT falha com duplicate/unique constraint:
     - Retorna PersistResult.remote(wasAlreadyPresent: true)
     - Tratado como sucesso

  4. Risco residual:
     - Se app reinicia entre INSERT OK e resposta ao App:
       proxima tentativa gera mesmo ID → banco trata como duplicate → OK
     - Se queue offline reenvia apos INSERT ja ter sido feito:
       duplicate error → treated as success → OK

  CONCLUSAO: Nao ha risco real de duplicidade. Idempotencia funciona.
