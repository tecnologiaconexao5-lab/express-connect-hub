3 — HTTP 406 ROOT CAUSE
==================================================

HTTP_406_ROOT_CAUSE=
  The table recrutamento_automacoes has ZERO ROWS in production.
  The eventProcessorWorker queries use .single() which expects
  exactly 1 row. When 0 rows are returned, PostgREST returns
  an error that the Supabase JS client surfaces as HTTP 406
  (Not Acceptable) — a content negotiation failure because the
  empty result set does not match the expected single-row format.

  The .single() modifier causes PostgREST to set:
    Accept: application/json
    Prefer: return=representation
    Expect: 200 OK with exactly 1 object

  When 0 rows match, PostgREST returns 406 instead of an empty
  array or null, because the response schema (empty array) does
  not match the expected schema (single object).

ROWS_MATCHING_QUERY=
  Query 1 (by id):       0 rows (table is empty)
  Query 2 (tipo+status): 0 rows (table is empty)
  ALL queries return 0 rows because the table has NO data.

EXPECTED_ROWS=
  Query 1: 1 row (expects automation by UUID)
  Query 2: 1 row (expects active validade_documento automation)

ACTUAL_ROWS=
  Query 1: 0 rows
  Query 2: 0 rows

6 — FREQUÊNCIA (WHY REQUEST REPEATS)
==================================================

WHY_REQUEST_REPEATS=
  The eventProcessorWorker runs on a 10-second interval
  (setInterval(cicloProcessamento, 10000)). Each cycle:
  1. Queries eventos_oficiais for unprocessed events
  2. For each recrutamento.* event, queries recrutamento_automacoes
     with .single() — fails with 406 (0 rows)
  3. Also runs executarScanDocumentos() every 5 minutes

  Additionally:
  - React StrictMode double-mounts components in development
  - Each mount triggers automacoesService.listar() via useEffect
  - The seed useEffect fires when automacoes.length === 0

  Result: 406 errors appear every 10 seconds when event processor
  is active, plus on each module mount/re-render.

8 — AUTH LOCK
==================================================

AUTH_LOCK_RELATED_TO_406=NOT_PROVEN

The @supabase/gotrue-js LockManager warning is a known Supabase
issue when multiple browser tabs open. It does NOT directly cause
HTTP 406 errors. The 406 is caused by .single() on empty results,
which is independent of auth state.

However, if the auth session is locked/expired:
- Requests use anon role
- anon has NO access to recrutamento_automacoes (REVOKE'd)
- PostgREST would return 401/403, NOT 406
- So auth lock is NOT the cause of this specific 406
