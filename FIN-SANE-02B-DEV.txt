3.2 RPC NOVA: f_confirmar_pagamento_fechamento

  Objetivo: tornar a baixa de fechamento atômica.

  Assinatura:
    f_confirmar_pagamento_fechamento(
      p_fechamento_id   UUID,
      p_data_pagamento  DATE
    )

  Retorno:
    JSONB { sucesso, mensagem, itens_processados,
            itens_ignorados, total_baixas }

  Lógica:
    1. Valida existência do fechamento.
    2. Valida que fechamento está aprovado (não pago).
    3. Para cada item vinculado:
       a. Encontra financeiro_pagar correspondente.
       b. Verifica se já existe baixa.
       c. Verifica se fp.valor = pp.valor_liquido.
       d. Registra baixa em financeiro_baixas.
       e. Atualiza financeiro_pagar.status = 'pago'.
       f. Atualiza pagamentos_prestadores.status = 'pago'.
    4. Se qualquer passo falhar, ROLLBACK total.
    5. Se tudo OK, COMMIT.

3.3 ATUALIZAÇÃO RETROATIVA

  Apenas registros NÃO PAGOS são atualizados:
    - status NOT IN ('pago','paga','cancelado','cancelada','estornado')
    - os_id IS NOT NULL
    - fornecedor_id IS NOT NULL
    - existe pagamentos_prestadores correspondente
    - tipo_pagamento IS DISTINCT FROM 'fechamento'
    - valor diverge de valor_liquido

  Snapshot criado antes do UPDATE:
    fin_sane_02b_snapshot(id, financeiro_pagar_id,
                          valor_anterior, valor_novo, os_id,
                          prestador_id, updated_at)
