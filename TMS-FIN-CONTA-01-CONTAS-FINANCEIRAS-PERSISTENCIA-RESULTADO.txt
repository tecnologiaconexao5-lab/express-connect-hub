--------------------------------------------------------------------------------
1. CAUSA RAIZ (provada)
--------------------------------------------------------------------------------
ConfigFinanceira.handleAddConta cria conta nova com ID TEMPORARIO de React:
  `id: \`c-${Date.now()}\``  (ConfigFinanceira.tsx:100)
Ao clicar "Salvar Contas", configFinanceiraService.salvarContasBancariasConfig
enviava esse id em um UPSERT com onConflict 'id':
  upsert([{ id: 'c-1790283538967', ... }], { onConflict: 'id' })
A coluna public.contas_financeiras.id e do tipo UUID (PK) -> o Postgres tenta
converter 'c-1790283538967' para uuid e falha:
  ERROR 22P02: invalid input syntax for type uuid: "c-1790283538967"
=> POST /rest/v1/contas_financeiras 400 Bad Request.
PROVA (rollback): INSERT id='c-1790283538967' -> "invalid input syntax for type uuid".

COLUNA QUE RECEBEU c-...: public.contas_financeiras.id (PK uuid).

2. SCHEMA REAL (contas_financeiras)
--------------------------------------------------------------------------------
id uuid PK DEFAULT gen_random_uuid(); nome text NOT NULL; tipo text DEFAULT
'Conta Corrente'; banco/agencia/numero_conta/digito/titular/chave_pix text NULL;
saldo numeric DEFAULT 0; saldo_inicial numeric DEFAULT 0; saldo_inicial_data date;
ativa boolean DEFAULT true; principal boolean DEFAULT false; empresa text;
plano_contas text; observacoes text; cor text; created_at/updated_at timestamptz.
- NAO possui tenant_id (tabela global).

  WHERE principal  -> no maximo UMA conta principal (regra ja existente no schema).
- RLS: policies TO authenticated (select/insert/update/delete USING true); nao ha
  policy para anon. Grants amplos para anon/authenticated/service_role.

3. FLUXO ANTES x DEPOIS
--------------------------------------------------------------------------------
ANTES:
  Nova Conta -> id 'c-<ts>' (estado React)
  Salvar Contas -> upsert com id 'c-<ts>' -> 400 invalid uuid -> nada persiste,
    UI permanece com o id temporario.
DEPOIS:
  Nova Conta -> id 'c-<ts>' (somente no estado React)
  Salvar Contas ->
    - existentes (UUID real) -> UPDATE pela PK;
    - novos (id 'c-...' ou vazio) -> INSERT SEM id (DEFAULT gen_random_uuid());
    - principal unica: se ha 1 principal, libera a vaga (unset nas demais) antes;
  -> sucesso -> REFETCH (carregar()) -> contas com UUIDs reais na UI.

--------------------------------------------------------------------------------
5. INSERT / UPDATE
--------------------------------------------------------------------------------
INSERT (novos): payload SEM 'id' -> banco gera UUID (gen_random_uuid()).
UPDATE (existentes): update(payload).eq('id', uuidReal) -> mesma linha, sem
  duplicar. Reexecutar sem mudanca atualiza a MESMA linha.
Principal: apenas 1 permitida; ao gravar uma principal, atualiza
  contas_financeiras SET principal=false WHERE principal=true AND id <> <nova>;
  se mais de uma principal no payload -> erro claro "Apenas uma conta principal...".

--------------------------------------------------------------------------------
6. UUID REAL / PERSISTENCIA / REFETCH
--------------------------------------------------------------------------------
INSERT sem id retorna UUID valido (ex.: a50bd0e7-903c-4d7d-a1a6-96cdedf0b3b8);
refetch por id retorna a conta; UPDATE pela PK altera a mesma linha. A UI passa a
exibir/editar com o UUID real apos o refetch.
