SECAO 3 — NAO USAR CONTADOR +1
---------------------------------

DECISAO= Contagem DERIVADA (SELECT count) em vez de campo materializado.

Justificativa:
  - qtd_operacoes na tabela prestadores sempre = 0 (nunca atualizado)
  - Contador +1 quebraria com reabertura, cancelamento, correcao, retry
  - Query agregada e idempotente por design
  - Sem necessidade de materializacao (193 alocacoes, query rapida)

SECAO 6 — LISTAGEM/HISTORICO DE OCORRENCIAS
----------------------------------------------

Ao abrir PrestadorDetalhe (edicao):
  → useEffect dispara carregarIndicadores()
  → SELECT * FROM prestadores_ocorrencias WHERE prestador_id = :id
  → setOcorrenciasReais(data)

Aba "Ocorrências":
  →_renderiza ocorrenciasReais (dados reais do banco)
  → Se vazio: "Nenhuma ocorrência registrada para este prestador"

Ao criar nova ocorrência:
  → INSERT em prestadores_ocorrencias
  → Refetch: SELECT * WHERE prestador_id = :id (releitura pos-INSERT)
  → setOcorrenciasReais(refreshed)
  → Toast sucesso
  → Lista e indicador atualizados imediatamente

Ao reabrir cadastro:
  → useEffect dispara novamente
  → Dados recarregados do banco
  → Ocorrência continua aparecendo

SECAO 8 — CASOS DE CONSISTENCIA
----------------------------------

T1 Prestador com 3 concluidas → Total Entregas = 3
   CONCEITUAL: OK. Query filtra por prestador_id + status='concluida'.

T2 Prestador com concluida + cancelada → cancelada nao infla total
   CONCEITUAL: OK. Filtro .eq("status","concluida") exclui cancelada.

T3 Mesma OS representada em multiplas tabelas → conta uma unica vez
   CONCEITUAL: OK. Contamos alocacoes (unidade atomica), nao OS.

T4 Operacao reaberta → nao permanece indevidamente como concluida
   CONCEITUAL: OK. Se status muda de 'concluida' para outro, count diminui.

T5 Conclusao APP/TMS → mesma regra/fonte operacional
   CONCEITUAL: OK. App motorista atualiza alocacoes_escala.status para 'concluida'.

T6 Prestador sem operacao → 0 real
   VALIDADO: PRESTADOR TESTE APP = 0.

T7 Ocorrencia existente → indicador correspondente
   CONCEITUAL: OK. ocorrenciasReais.length exibe contagem real.

T8 Ocorrencia criada em QA → aparece apos refetch
   IMPLEMENTADO: Refetch apos INSERT confirma listagem atualizada.

T9 Ocorrencia de outro Prestador → nao entra na contagem
   CONCEITUAL: OK. Filtro WHERE prestador_id = :id.

T10 Nenhum vinculo por nome/placa/texto
   CONFIRMADO: Todas as queries usam UUID (prestador_id).

SECAO 9 — PERFORMANCE
------------------------

                         Index: prestador_id + status (composto)

                           Index: prestador_id
                           Executado 1x ao abrir edicao + refetch pos-INSERT

  - Total: ~193 alocacoes no sistema (rapido)
