2. CAUSA RAIZ DOS FALHAS ENCONTRADAS
═══════════════════════════════════════════════════════════════════════════════

2.1 Tipo de composicao_financeira_os.os_id
    A coluna composicao_financeira_os.os_id é TEXT (não UUID). Tanto M66
    quanto M80 passavam UUID diretamente para WHERE os_id = NEW.id / v_os_id,
    gerando:

        operator does not exist: text = uuid

    Como ambas as funções envolviam o INSERT de OS dentro de blocos
    EXCEPTION WHEN OTHERS THEN NULL, o erro era engolido e a OS nunca era
    criada.

2.2 Campos jsonb de ordens_servico
    A migration forward já usava to_jsonb(...) para adicionais/ajudante, mas
    o rollback ainda passava NUMERIC direto, causando:

        column "adicionais" is of type jsonb but expression is of type numeric

2.3 Uso de NEW.cliente_id/prestador_id como UUID no rollback M80
    O rollback M66 preenchia ordens_servico.cliente_id e prestador_id com os
    NOMES do cliente/prestador (TEXT). O rollback M80 tentava
    NEW.cliente_id::UUID / NEW.prestador_id::UUID, falhando com:

        invalid input syntax for type uuid: "Cliente Rollback"

    Correção: usar NEW.cliente / NEW.prestador (UUIDs reais) no M80.
