O PROBLEMA REAL afeta apenas 3 alocacoes de producao real + 5 anormais.

ROOT CAUSE IDENTIFICADA:
  O App Motorista (Flutter) tem DOIS CAMINHOS separados para persistir POD:
    1. DeliveryProofRepository.create() → INSERT em delivery_proofs (APP-ONLY)
    2. RPC f_atualizar_etapa_app → UPDATE em alocacoes_escala (APP + TMS)
  NENHUM dos dois caminhos produz delivery_proofs quando ha falha intermediaria.
  O TMS web (podService.finalizarComPOD / escalaService.finalizarAlocacao)
  NAO insere em delivery_proofs — apenas em entregas_protocolo.

  Causa direta das3 alocacoes GO-LIVE: motorista 6cc41f68 aceitou operacoes,
  mas o insert em delivery_proofs falhou (catch silencioso no App) e a
  finalizacao foi completada via TMS web (escalaService) que NAO cria DP.

7. FIX P1 — MONITORAMENTO
═══════════════════════════════════════════════════════════════════════════════════════

7.1 AUDITORIA PERIODICA (SQL)
  -- Detectar alocacoes finalizadas sem delivery_proof (producao real)
  SELECT ae.id, ae.data_finalizacao, ae.prestador_id, os.numero
  FROM alocacoes_escala ae
  LEFT JOIN ordens_servico os ON os.id = ae.ordem_servico_id
  WHERE ae.status = 'concluida'
    AND ae.finalizada = true
    AND ae.prestador_id IS NOT NULL
    AND ae.aceite_prestador = true
    AND NOT EXISTS (
      SELECT 1 FROM delivery_proofs dp
      WHERE dp.operation_id = ae.id::text OR dp.stop_id = ae.id::text
    )
  ORDER BY ae.data_finalizacao DESC;
