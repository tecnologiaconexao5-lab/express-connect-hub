MUDANCAS NA RPC:
  1. DROP FUNCTION (necessario para mudar aridade)
  2. Novo parametro: p_valor_pago NUMERIC DEFAULT NULL
  3. Logica de valor: se p_valor_pago > 0 usa parcial, se NULL usa integral
  4. Rejeicao explicita: p_valor_pago <= 0 retorna erro
  5. Match FP: tenta por valor exato primeiro, depois por saldo > 0
  6. Validacao: v_valor <= v_saldo (nao excede saldo)
  7. Baixa: cria com valor_baixado = v_valor, saldo_restante = v_saldo - v_valor
  8. FP status: 'parcial' quando saldo > 0, 'pago' quando saldo = 0
  9. PP status: mantem 'pendente' quando parcial, 'pago' quando quitado
  10. Retorno: saldo_restante = v_saldo - v_valor

DIFF EXATO (before vs after):
  - DROP FUNCTION f_confirmar_pagamento_prestador(uuid, date)
  + DROP FUNCTION (implicito)
  + CREATE FUNCTION f_confirmar_pagamento_prestador(uuid, date, numeric)
  + p_valor_pago NUMERIC DEFAULT NULL (novo parametro)
  + IF p_valor_pago IS NOT NULL AND p_valor_pago > 0 (parcial)
  + ELSIF p_valor_pago IS NOT NULL AND p_valor_pago <= 0 (rejeitar)
  + Match por saldo > 0 (fallback apos match por valor)
  + IF v_valor > v_saldo THEN rejeitar
  + IF (v_saldo - v_valor) > 0 THEN status='parcial'
  + PP: mantem pendente quando parcial
