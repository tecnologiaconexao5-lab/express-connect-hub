10 — ROOT CAUSE
==================================================

TABLE_NOT_FOUND_ROOT_CAUSE=CLIENT_MATCH

A tabela Mineirao NAO e encontrada porque:

1. A Escala (EscalaLista.tsx:179-183) busca por:
   .eq("cliente", normalizeClienteNome("Mineirao Abc"))
   .eq("tipo_veiculo", "fiorino")

2. normalizeClienteNome("Mineirao Abc") = "MINEIRAO ABC"
   (trim().toUpperCase() — clienteHelper.ts:1-3)

3. A coluna "cliente" na tabela Mineirao contem:
   " Mineirao Abc" (com ESPACO ANTES do M)
   (razao_social do clientes: " Mineirao Abc Paes de Queijo e Salgados Congelados LTDA")

4. Postgrest .eq() compara strings exatas:
   "MINEIRAO ABC" != " Mineirao Abc"

5. Portanto a query retorna 0 resultados.

6. A busca por tabela universal (line 210-217) tambem falha:
   tabela.universal = false

7. Resultado: Nenhuma tabela encontrada.

O problema NAO e:
  - thermal mismatch (exigencia_termica=null, nao filtrado)
  - vehicle mismatch (tipo_veiculo="fiorino", match OK)
  - status mismatch (ativo=true, match OK)
  - validity mismatch (dentro da vigencia, match OK)

O problema E:
  - CLIENT NAME MISMATCH por espaco anterior no campo "cliente"
  - normalizeClienteNome() faz trim no INPUT mas nao no DB
  - A coluna "cliente" no DB tem espaco anterior (dados sujos)

THERMAL_LEVEL_TERMICO_REQUIRED=NO (para este bug especifico)
  O nivel "Termico" nao e necessario para resolver o bug atual.
  O match falha no CLIENTE, nao no termico.

CODE_FIX_REQUIRED=
  Opcao A (correcao pontual): EscalaLista.tsx normalizar o nome ANTES de comparar
    Ou usar .ilike() em vez de .eq() para cliente
    Ou trim() no DB (migration)
  
  Opcao B (correcao estrutural): usar buscarTabelasService em vez de lookup local
    A Escala define sua propria buscarTabelaValoresCliente (shadowing)
    O service buscarTabelasService resolve nome do DB (resolverNomeCliente)
    e faria match correto

DATA_FIX_REQUIRED=
  Corrigir " Mineirao Abc" → "Mineirao Abc" na coluna "cliente"
  (remover espaco anterior)
  OU
  Corrigir o razao_social no clientes (remover espacos)

MIGRATION_REQUIRED=OPCIONAL
  Se optar por migration de dados:
    UPDATE tabelas_valores SET cliente = TRIM(cliente) WHERE cliente != TRIM(cliente);
  Isso corrige TODAS as tabelas com espacos.
