2. CAMINHO ANTIGO REMOVIDO/DESABILITADO
--------------------------------------------------------------------------------
O botao "Liberar Lote" (que apenas fazia handleAtualizarStatus(id, {
status_pagamento: 'em_lote' }) SEM criar lote_id) foi REMOVIDO. No lugar ficou
apenas um texto informativo "apto p/ lote". Nao existe mais nenhum caminho que
grave status_pagamento='em_lote' diretamente pela UI. A UNICA forma de formar
lote e o botao "Gerar Ordem/Lote de Pagamento" -> RPC f_gerar_lote_pagamentos.

--------------------------------------------------------------------------------
3. MODAL DE CONFIRMACAO
--------------------------------------------------------------------------------
Dialog no padrao do TMS (sem window.confirm/alert) exibindo:
  - quantidade de pagamentos;
  - quantidade de prestadores;
  - periodo minimo/maximo dos servicos (min/max de periodo_inicio);
  - total liquido do lote;
  - resumo por prestador (qtd + total).
Botoes: "Cancelar" e "Gerar Ordem/Lote". Sem dados bancarios.
Calculos por resumoLoteSelecionado (helper puro).

--------------------------------------------------------------------------------
4. CHAMADA RPC E TRATAMENTO DE RETORNO
--------------------------------------------------------------------------------
Ao confirmar: gerarLotePagamentos(ids) -> supabase.rpc("f_gerar_lote_pagamentos",
{ p_ids }). Trata {lote_id, solicitados, incluidos, ja_em_lote, bloqueados,
detalhes}.
  - bloqueados>0 -> toast de erro com os motivos (RPC all-or-nothing, sem
    sucesso parcial);
  - lote_id -> toast "Lote gerado com sucesso — <8chars> · N pagamento(s)" +
    limpar selecao + refetch;
  - ja_em_lote -> toast informando lote existente + limpar selecao.
NAO chama pagamento/baixa/banco.

--------------------------------------------------------------------------------
5. POS-SUCESSO
--------------------------------------------------------------------------------
Selecao limpa; consulta atualizada (fetchPagamentosManuais + fetchPagamentos);
registros passam a "Em Lote" com o lote_id curto (8 chars) + botao copiar ID
completo. Itens ja em lote tem checkbox DESABILITADO (isAptoLote exige
lote_id nulo) — nao podem ser selecionados de novo.

--------------------------------------------------------------------------------
6. TESOURARIA — QUERY ANTES x DEPOIS
--------------------------------------------------------------------------------
ANTES: pagamentos_prestadores WHERE impacto_dre = true ORDER BY
       data_prevista_pagamento LIMIT 50 (mostrava aprovados sem lote tambem).
DEPOIS: status_aprovacao='aprovado' AND elegivel_lote=true AND
        status_pagamento='em_lote' AND lote_id IS NOT NULL AND is_teste=false
        (respeitando RLS/tenant). Mostra SOMENTE lote realmente formado.

--------------------------------------------------------------------------------
7. AGRUPAMENTO POR LOTE_ID (sem tabela cabecalho)
--------------------------------------------------------------------------------
agruparLotesTesouraria calcula a partir das linhas: 1 grupo por lote_id com
  - ID curto do lote (8 chars) + copiar;
  - quantidade de pagamentos;
  - quantidade de prestadores;
  - total liquido;
  - periodo dos servicos (min/max);
  - status visual "Aguardando execucao bancaria" (NAO persistido).
Cards: lotes aguardando, pagamentos em lote, total liquido em lote.
