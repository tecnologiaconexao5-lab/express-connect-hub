handleCreateReserva (EscalaLista.tsx):
  bloqueava o salvamento quando nenhuma OS estava selecionada:
    if (!novaOSId) return toast.error("Selecione uma Ordem de Serviço antes de salvar a alocação.");
  O payload já suportava OS opcional; o INSERT chama criarAlocacao().

escalaService.criarAlocacao:
  "Auto-associate or create Ordem de Serviço (OS) if not provided" — se !ordem_servico_id:
    • procura OS existente (cliente_id + prestador_id + data + tipo_veiculo) → vincula;
    • senão cria via criarOrdemServico() (numero OS-YYYYMM-######, is_teste default false)
      ANTES de inserir a alocação.

criarOrdemServico (ordemServicoService):
  gera numero oficial (OS-{ano}{mes}-{seq}) — sem numeração fictícia; custo_prestador=0
  (sincronizado depois pelo M66).

M66 (pós ESCALA-E2E-05):
  INSERT ... ON CONFLICT (id) DO UPDATE → idempotente; não cria uma segunda OS.

Risco de dupla OS: NÃO — a OS é criada UMA vez pelo service (ou vinculada) e o M66 apenas
faz upsert pela mesma id.
