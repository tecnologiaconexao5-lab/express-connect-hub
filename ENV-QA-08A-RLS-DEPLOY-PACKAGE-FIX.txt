## Summary

Corrected blockers identified in ENV-QA-08 production preflight. Created idempotent deploy package that removes insecure `anon`/`public`/`USING(true)` policies and adds scoped RLS policies. Verified idempotent (applied 3× without errors). All 18 RLS tests pass.

## Key Findings

### ENV-QA-08 Blocker Resolved

| Issue | Resolution |
|-------|-----------|
| Migration 1 not idempotent (CREATE POLICY without IF NOT EXISTS) | Deploy uses `DROP POLICY IF EXISTS` before every `CREATE POLICY` |
| Portal Cliente anon key for `clientes` SELECT | Investigated: Portal Cliente uses **authenticated session** (not anon). Anon removed from `clientes_select_own`. |
| `portal_ocorrencias.os_id` column doesn't exist | Policies use `cliente_id` + `f_obter_cliente_id_do_usuario()` instead |

### Portal Cliente Investigation

- **File:** `src/pages/PortalCliente.tsx:1320`
- **Method:** `supabase.from('clientes').select('*').eq('id', clienteId).maybeSingle()`
- **Auth:** `supabase.auth.getSession()` → authenticated JWT
- **Anon key usage:** None — `VITE_SUPABASE_ANON_KEY` is used only for initial client creation
- **Conclusion:** Removing `anon` from `clientes_select_own` is SAFE
